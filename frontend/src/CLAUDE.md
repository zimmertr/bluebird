# Frontend layout

Every module under `frontend/src/`: what it owns, and why it is separate. This
file is one half of the module layout that used to sit in the repo root's
[`CLAUDE.md`](../../CLAUDE.md), and it is loaded only when a session touches this
tree. Everything that governs a change to these modules — the design-system rule,
the memoization rule, the Python/TypeScript mirrors table, the interaction model —
stays in that root file. Read it first; this is a directory, not a manual.

**A new source module gets a bullet here, in the same PR that adds it.** The bullet says what the module OWNS and why it is separate, at the density of the ones around it; one line is a fine answer for a twenty-line module. Nothing enforces this. A session reads this list before it writes code, so a module named nowhere here is one the next session rediscovers and re-decides (#392).

The bullets for `utils/`, `components/`, `hooks/` and `map/` live in a `CLAUDE.md` in each of those directories: [`utils/CLAUDE.md`](utils/CLAUDE.md), [`components/CLAUDE.md`](components/CLAUDE.md), [`hooks/CLAUDE.md`](hooks/CLAUDE.md) and [`map/CLAUDE.md`](map/CLAUDE.md). A new module in one of them gets its bullet in that file. This file keeps the modules directly in `src/` and in `src/testSupport/`, and each bullet that names modules in two of those directories.

- `src/hooks/useForecastSelection.ts` + `src/utils/forecastSelection.ts` — the panel's When and Model state, cut out of `App.tsx` (#409): the selection, the ranking model, the compared models, the clamp notice and the pre-clamp memory, plus the three things read off them every render (`panelWindowMs`, `panelPointSample`, `windowWarning`). One hook because a model change edits the window, so the two cannot be owned apart without handing each other setters. The rules are pure and live in the util: `planModelChange` is the clamp and its undo (a pre-clamp window comes back whole the moment a model can serve it, and a chain of clamps remembers the FIRST window), `panelWindowMs` the whole-day stand-in a dateless selection borrows, and `windowWarningFor` the horizon warning. `forgetPreClamp` is the one call an analysis makes, because a report pins the window it asked and a restore after it would disagree with the screen. The linter's `forecast-selection-hook` check keeps `panelPointSample` read off the PANEL window, where the report's `pointSample` stays in `App.tsx` (#485)
- `src/hooks/usePopover.ts` + `src/components/Popover.tsx` — the impure half of `utils/listbox.ts`, and the one recipe every floating panel follows (#385). Four components carried a copy of it and three had been built by copying the fourth, so a fix to one reached none of the others. **The hook is the wiring**: the two placement passes, both before paint (ask for the whole viewport so the panel lays out at its natural height, measure that height, place again knowing it — without the measurement the placement cannot tell "taller than the gap" from "taller than the screen", and every panel scrolls in the gap); the measuring ref, which runs after EVERY commit rather than keyed on `open`, because the panel does not exist yet when an `[open]`-keyed pass would run and the unmeasured fallback then sticks for the whole open; following the trigger on `resize` and on capture-phase `scroll`, since the panel is fixed and the trigger sits in a scrolling column; and the dismissal — Escape, which hands focus back to the trigger, and an outside **`pointerdown`, never `click`**, because a click landing on something that unmounts under it never reaches document and a press that starts outside has to dismiss before the map treats it as a gesture. The trigger is exempt, or its own toggle fires close-then-reopen. **The shell is the drawing**: the `SURFACE_CARD` wrapper, `LAYER.popover`, the fixed box, the portal to `document.body`, and an optional overline header row that two of the four had spelled separately. `remeasure` is what a panel whose height changes while it is open declares, and it is **empty by default**: a panel that re-places itself as its rows change can jump across its trigger under the hand pressing a row, which is worse than one that shrinks where it stands. `ModelPicker` is the one exception, because its chip row GAINS a line as models are ticked and would otherwise scroll in a gap the viewport could have given it outright. `preferredWidth` defaults to the 256px a list of labels takes; `ModelPicker` passes its own measured 380px because its rows carry prose
- `src/styles.ts` — the type ramp plus the surface/button/field roles, and `LAYER`, which names the stacking order; components compose these instead of picking sizes, colors and z-indexes at the call site (`src/styles.test.ts` enforces it). `LAYER` exists because the model picker shipped *behind* the mobile drawer that contains it, the two values having been chosen in different files and never compared
- `src/metrics.ts` — the one vocabulary for the six metrics: nouns (spelled out), units, aggregates (their short forms: `Avg`/`Min`/`Max`), and the composers behind the results header and table headers; `SNAPSHOT_FAMILIES`/`isSnapshotFamily` name the families that are ONE number rather than a reduction over the window (snow depth, #449), which is what makes `aggregateToken` and `windowAggregate` answer `null` for them, `rankedNoun` leave them bare in both modes, and `ChartMetric` exclude them by type rather than by a check at each call site — a second such metric is one entry in that list; a family's key is also a reserved key PREFIX, because `familyOf` splits on the first `_`; the map legend titles itself with the bare noun and leaves the hour/window framing to those surfaces. **A surface never spells a metric's name itself** — an ESLint rule fails a literal `Precip`/`Temp`/`Avg` in a string or a template across the twelve consuming files. Precipitation's two formatters (`formatPrecipTotal`, `formatPrecipRate`) live here for the same reason, and `src/metrics.test.ts` reads the same twelve files as text and fails a `toFixed` on a precipitation value: the chart's tooltip printed three digits while the rate cell beside it printed four, so one quantity had two lengths on one screen (#395). Three digits, total and rate alike — the rate cells are shaded on the NWS intensity classes, whose finest boundary is 0.01 in/hr, so a digit is a hundredth of the smallest distinction the colour makes. The digit count is a display decision only: the API answers four decimals and is untouched

The popover hangs off a button **under the search box, top-left**, wearing the same `BUTTON_FLOATING` as Controls: they are the app's only two map buttons, they stack in one column, and a size difference between them read as a mistake rather than a hierarchy. It was first put beneath MapLibre's own zoom/compass/geolocate stack on the right at a measured offset, which clipped the geolocate button: that stack is two control GROUPS with a margin between them, so any offset clearing it is a guess. The left column is the app's own map controls (Controls, search, Layers) and the right is the library's, which is the split worth keeping. Both columns measure off ONE inset: `MAP_EDGE` in `styles.ts` publishes `--map-edge-inset` (12px) on the map wrapper, the app's column and the legend stack read it for their top and left, and `map.css` reads the same property for the vendor stack's own margin — the library ships 10px, which started its buttons a step above the Layers button opposite them. The linter's `style-map-column` check fails an inset spelled at any of those call sites, and `styles.test.ts` does the same for `map.css`, which ESLint does not read. It dismisses on outside `pointerdown` and Escape — `pointerdown` rather than `click` so a press that starts outside dismisses before the map treats it as a gesture. It is the one floating box that is a **menu rather than a key**, so it wears `SURFACE_POPOVER` rather than the legends' `SURFACE_FLOATING`: one step of fill and a heavier shadow, with the border unchanged, because a box the reader acts in must not read as a box the reader only reads. The lighter fill is what `LIFTED_EDGE` exists for — slate-500 carries a well's 3:1 boundary against the panel and only 2.17:1 against this surface, so the segment and the coverage slider inside it take slate-400 instead (`SEGMENT_FLUID_LIFTED`). The `Options` panel section is **gone**, and since #341 so are `Ranking` and `Filters`: one `Metrics` table carries each metric's radio, aggregate dropdown and two bound boxes on one row. It reads in two blocks with NOTHING drawn between them (a rule was tried in both weights and rejected: that weight only ever says a new section begins). First the two wide controls that say how the list is ordered, `Rank by` — one segment, because the direction is a property of the ranking rather than of each metric, and four of five per-row segments were always disabled — and `Max results` under it. Then the `Min`/`Max` headings. Then the rankable metrics, one row each, alphabetically by noun; a snapshot family renders no aggregate dropdown and leaves that grid cell empty, because the four tracks are what line its bound boxes up with the two wide controls above (#449). What tells the blocks apart is shape, two wide controls over a table of narrow ones. The units live in the boxes' placeholders, because `Freezing level (ft)` does not fit beside three controls. `Include unnamed peaks` moved beside the destination types it widens. Indenting the layer rows under a heading was tried and reverted before that move; do not reach for it again. Blocks shows *where the samples are* and overstates only its edges; smooth shows the field and hides how few samples are under it. Blocks was the default on that reasoning until #460, when TJ chose the field: a map whose markers take a continuous colour from `interpolateRgb` and whose grid paints a hard rectangle per sample reads as two encodings of one scale, and the honesty the blocks view carried is carried by the pitch the legend states instead. The segment and the `grid=` parameter both stay, so the sample view is one press away and a shared `grid=blocks` link still opens what it named. **Smoothing is between MODEL GRID POINTS, which is what makes it legitimate where #121's rejected raster was not**: Open-Meteo answers a coordinate with its containing grid cell's value, so sampling at the model's pitch means neighbouring samples are neighbouring grid cells and the blend between them is one the model already treats as continuous. #121's objection was to interpolating between *destinations* across a valley, and it still stands. The honesty rule now rides on the pitch, which the legend states. Coarsening **loops** rather than rebuilding once: counts come out of `Math.ceil`, so a lattice a few samples over the cap is not fixed by scaling the pitch a few percent. It returns the *effective* pitch and the legend prints it. Nothing here mirrors a color decision: `fillColor` and `bearingAt` are imported from `resultFeatures.ts` (exported for this), so the field and the marker standing on it cannot be scored differently, and `NO_VALUE` is imported to be *recognized* — a sample with no number goes transparent rather than grey, because a marker must stay on screen and the field must not assert what it does not know. Three subtleties are pinned by tests and easy to reintroduce: the raster's rows are **flipped** (a lattice counts north from its south-west corner, an image counts south from its top-left), a gap's RGB is **bled from a neighbour** (bilinear magnification samples colour from transparent pixels too, so a hole left at black rings itself in black), and `gridImageCoordinates` returns the lattice's **outer** bounds so pixel centres land on samples rather than half a cell off. A field straddling the antimeridian returns `null`, the same geometry the national fire snapshot sidesteps by never taking a bbox

- `src/hooks/usePacedFetch.ts` + `src/utils/pacing.ts` — the client pacer's countdown, owned once (#394). Three fetches draw on one weighted Open-Meteo budget — the ranked analysis, the forecast grid and the model comparison — so any of them can be put to sleep by work another one started. Each used to keep its own `paceEndMs`, which is why the comparison was silent: reporting the wait was a thing a caller remembered to wire rather than a thing the pacer carried. `pacing.ts` is the reducer, the seconds left, and the one wait line ("Open-Meteo quota: resuming in Ns"); the hook is the state and the one-second tick. **Every caller of `fetchWeather` that has somewhere to say so hands over `onPace`**, and the linter's `app-paced-fetch` check reads the three hooks so a fourth cannot ship silent. The state is a DEADLINE rather than a count, because `fetchWeather` reports a duration once and everything after that is the clock's job; a wait already past reads as `null`, so a surface asks one question instead of two. The map's grid legend spells the same wait `Waiting · 45s` (`gridLegendLine`) rather than as prose, because it is a key's value beside a label and vertical space on the map is the scarcest thing the app has, and it clears that wait on EVERY chunk that lands rather than on the first, because a chunk in hand is a chunk the pacer let through (#432). The comparison says it in TWO places rather than one: the chart's own line while a comparison is drawn there, and otherwise one line under the results bar in `ResultsBar.tsx`, because the table's per-model rows are bought as soon as a second model is selected, so air quality ranked, nothing charted, or the table shown by itself would each leave a paced fetch with a wait and no surface (#433); `compare.active && chartShowing` is the predicate that keeps one wait from being said twice, and the linter's `app-compare-pace-bar` check pins it
- `src/logo.ts` — the icon at the size the app actually draws it. `public/icon.png` stays where it is at 1024px, because the Open Graph card and the iOS home-screen icon need one absolute URL and a large square; serving that file for an 80px panel header cost every cold load three times the whole JavaScript bundle over the wire, for an image no wider than a thumbnail (#337). Importing the file rather than pointing at a public path is what earns it a content hash, and a hashed name under `assets/` is the one thing the cache-header middleware answers `immutable` for (#354)
- `src/testSupport/fixtures.ts`: the one place a fake is spelled in full (#425): a result row, its hourly series, one model's weather answer, one published forecast model, one geocoded place, one forecast-grid sample and its cell, one fire warning (`fireWarning`), one pending destination (`pendingDestination`), one discovered destination (`discovered`), and an HTTP answer (`fakeResponse`, a real `Response`, JSON or a raw body). Typed against the real interfaces rather than cast, so a new field is one edit here and a missing one fails this file alone. Both Vitest projects read it, so it holds data and types and imports nothing that runs
- `src/testSupport/render.tsx`: what every component test starts from. `render` wraps Testing Library's and hands back a `userEvent.setup()` user, so every suite drives the page one way and a held key or button carries across the actions of one test the way it does for a reader. `placeAt` gives one element a box, because jsdom lays nothing out and every element otherwise measures zero at the origin; a placement or drag test says where the few boxes it reads are rather than stubbing layout for the page. Loaded by the DOM project only
- `src/testSupport/stubMap.ts`: the one stand-in for a MapLibre map, which neither Vitest project can construct (it needs WebGL). It keeps the layer stack in draw order, honouring a `before`, so a test can assert where a module inserted a layer; records every call; holds the sources a module adds; and fires the handlers a module registers, by event and layer. Every module under `src/map/` is tested against it, and a second stub spelled inside a test is the drift #389 unwound for result rows
- `src/testSupport/setup.ts`: the DOM project's setup file, and nothing else loads it. It unmounts after every test (Testing Library does that alone only when the runner exposes globals, and this config does not), clears storage between tests and sets the welcome flag through `viewPrefs.ts` so a rendered app is not hidden behind the first-run modal, and supplies the three element methods jsdom lacks and the components call as side effects (`scrollIntoView`, `setPointerCapture`, `releasePointerCapture`), as no-ops, since jsdom has nothing to scroll or capture
