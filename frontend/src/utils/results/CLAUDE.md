# Frontend layout: `src/utils/results/`

- `src/utils/results/resultsCsv.ts` — the displayed report as a file (`buildResultsCsv`, `csvFilename`). Pure and DOM-free so it is testable under the node-env Vitest; the Blob and anchor live in `utils/exportCsv.ts`. Takes rows already in display order and columns already resolved — it re-derives nothing, because a second answer to "what is on screen" is the bug `present.ts` exists to prevent. A `null` fire map **keeps the wildfire column and writes `N/A` in every ranked row** instead of a blank, and a `null` `CsvOptions.closureWarnings` does the same for the Closure column (#550: the bare order name, an empty cleared cell, `N/A` outside the area feeds' eight-state coverage, and a `Closure data by US Forest Service` credit row whose second cell is the source's link, since the orders carry no license): on screen an empty flag column self-corrects when the ⚠️ arrives a moment later, but a file is read detached from the app, where a column of blanks asserts that every row was checked and cleared. Both columns are always in the header, so every file has the same columns (record 0241). Below the data, a metadata block states the analyzed window as `Forecast start` and `Forecast end` rows, plus one `Forecast end (<model>)` row per compared model that ends inside the window (#493, `CsvOptions.modelEnds`, in the picker's order), so a spreadsheet can compute the hours a short model's plain numbers cover. The mark rides the Model cell (`NOAA HRRR*`, via `isPartialRow`) and never a number, which would turn the column into text (#508), and one row holding `PARTIAL_COVERAGE_NOTE` follows the model rows only when the file carries the Model column and a marked row, because the note explains a mark on that column. A row read at the terrain height (`readAtTerrainHeight`) writes that height plain in the Elevation column and the dagger on its Name cell (`Raven Ridge†`), with `TERRAIN_HEIGHT_NOTE` behind its own blank row after the model note, on the same terms: only while the file carries the Elevation column and such a row. Record: [0116](../../../../docs/decisions/0116-no-recorded-elevation-shows-terrain-height-marked.md) The supplier credits close the file, each as the words and then a link, and only for the suppliers the file used: Open-Meteo and OpenStreetMap always, then one row per credited column in the order the columns stand: NIFC with the wildfire column, and the Forest Service with the Closure column. Snow depth's NOHRSC row left with its column (#678): snowfall is Open-Meteo's, which the first row names
- `src/utils/results/resultsCells.ts` — what a results-table cell SAYS: the wildfire text and its hover note, the Closure cell's (`closureCell`, the same three states), the Model column's fallback, the N/A of a metric that declined to answer, the printed value (a null prints the dash before any formatter sees it, since snowfall's formatter is precipitation's and would print zeros; a short model's mark is not here but on the Model cell, which `ResultsTableRow.tsx` raises in `TABLE.mark`), a ranked cell's colour (`cellColor`, both inks in one style, and `cellTint`, the same tint with its inks apart for the map popup), the Windy link, the rank, and the row keys. Apart from `ResultsTableRow.tsx`, which is the markup, so each decision is testable under the node-env Vitest without rendering a table
- `src/utils/results/resultsSheet.ts` — the phone results sheet's arithmetic (#249): the sheet's height, the map floor it rests above, and the one lift every piece of the map's bottom chrome measures from. On a phone the results stand ON the map instead of taking a share of the column, so the legend, the timeline and MapLibre's own bottom-right corner all clear the sheet's top edge rather than the screen's — same gaps, new datum. The resting floor counts the timeline's band whether or not a bar is on screen, because a map overlay must never resize the results. `SHEET_HEADER_PX` (71px: the bar on one line on every phone since #687, its controls 32px tall since record [0223](../../../../docs/decisions/0223-finger-controls-draw-32.md)) is the one measured number on a phone and it is also the collapsed height (a desk's `RESULTS_BAR_PX` is the one-line bar, and only the estimate before `useResultsLayout` measures the bar, #714): round it UP if it is re-measured, since an over-estimate leaves a gap where an under-estimate hides a legend row. **Two floors, not one.** The resting floor holds until the reader takes a grip; `draggedMapFloorPx` holds however far they pull, and it keeps the rows and the Analyze button's strip (`DRAGGED_MAP_PX`), so a sheet dragged to the top never pushes the transport through a chip. `restingLiftPx` is a third number and belongs to the camera: `fitBounds` and `flyTo` frame into the whole container, which on a phone runs on behind the sheet, so every framing call in `MapView` takes it as a bottom padding. It is derived from the DEFAULT panel heights, so a drag never re-frames the map under the hand that is dragging it. Those defaults are `DEFAULT_PANEL_HEIGHT` (220), held here because two panels of it must fit under `dockedMapFloorPx` on a 1000px window. Pure because `MapStage.tsx` renders the map, which no Vitest project can stand up without a mock, and these are the numbers that decide whether a legend is on screen at all. **Two panels need room for two**: `bothFits` in `layout.ts` measures the space below the map against the drag floor plus two panel floors, and under that line — 652px of viewport at 360px wide, measured 2026-10-13 against `draggedMapFloorPx(2)` (672 until #687 put the bar's actions on one line of glyphs and the header lost 20px) — the results bar disables Both and the sheet draws the one panel the reader last chose instead (#430, `resolveResultsMode`), because two panels pinned at their floor leave both grips with nothing to move; the stored preference is never rewritten by that fallback, so a taller viewport gives Both back with no press. Record: [0034](../../../../docs/decisions/0034-phone-sheet-on-map.md) Since #696 it also places a phone's foot: `fabBottomPx` (the Analyze button, 16px over the sheet's edge, never over the rows), `transportStandPx` and `transportFits` (the player on the button, off the map while there is no room), and `DRAGGED_MAP_PX`, now the rows (`MAP_ROWS_PX`, 92) and the button's strip (`FAB_STRIP_PX`, 88), so a full sheet stops 180px down. Record: [0135](../../../../docs/decisions/0135-phone-opens-on-the-map.md) A phone's scale and (i) stand on the button's row (`phoneCornerLiftPx`); the Controls sheet is `controlsSheetPx` tall, the map less `CONTROLS_MAP_PX`, 256, which keeps the 76px the notice band of record 0140 had above it so the sheet opens where it did when the band went with the message badge (record 0208; taking the room back is the maintainer's call), and the button, the player and the corner stay on the results sheet's edge while it is up; `resolveSheetLift` takes the home indicator band as the datum with no sheet (`footPx`). Record: [0208](../../../../docs/decisions/0208-analyze-button-counts-the-messages.md) Record: [0207](../../../../docs/decisions/0207-phone-controls-sheet-is-modal.md) Record: [0152](../../../../docs/decisions/0152-sheets-end-above-the-home-indicator.md) The scale and the (i) stand with their bottoms on the button's bottom edge (`phoneCornerLiftPx`), and a dragged Controls sheet rises to `controlsFullPx`, the map less the button's strip under the chips (#696). Record: [0146](../../../../docs/decisions/0146-sheet-grips-drag.md) A resting sheet still reserves `RESTING_TOP_PX` (156) above the legend's room, the inset it was sized to in #249, so the half height a reader knows stays put. A desk's legend card is capped by `legendMaxCss`: the map's own height (`100cqh`) less the rows and the floor `legendBottomPx` keeps (#714). Record: [0174](../../../../docs/decisions/0174-desk-map-rows.md) It clears the player's band only on a map narrower than `LEGEND_BESIDE_TRANSPORT_PX` (864px, `100cqw`), where the centred bar reaches under the card; wider, the card keeps the plain gap with the player on.
