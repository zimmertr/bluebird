# Frontend layout: `src/components/`

- `src/components/ForecastCalendar.tsx` — the whole forecast window in one card: a **When** segment picking Current or Dates, an **Hours** segment under it, and the month grid below both. The two segments sit above the grid rather than around it, so the two decisions the window needs read as one block and neither lands below the fold; the grid and the Hours row appear only under Dates, the way the hour fields appear only under Hourly, because Current takes no input at all. "Dates" names the second arm rather than Days or Range because it must be silent about count *and* tense: 55 of the 71 days it reaches are behind today (#234). Holds no date logic of its own (see `utils/calendar.ts`); a mouse drags a range, a finger taps twice, and the selection commits on pointerup so a drag never re-renders the panel per pointermove. Cell brightness is one channel carrying one meaning — **how much of that day the app can serve** (`DayAvailability`) — which is why an adjacent month's days are drawn blank rather than dimmed
- `src/components/SearchBox.tsx` — floating map search (Nominatim place lookup + local coordinate parsing; Enter-to-search only, per Nominatim's no-autocomplete policy)
- `src/components/ResultsTable.tsx` — sortable results table, and *only* the rendering of one: it receives its rows already in display order. It is the frame: the header, the empty reason, and one memoized row per destination (a row a live knob cuts is simply no longer drawn, with no exit animation, because a row outside `results` has no element left to fade), keyed by `rowKeys` (the coordinate and the compared model) so a sort moves rows rather than re-keying every one. The chart handlers come from `useChartBox` and the fire clock from `FireClock`, so neither a chart toggle nor a clock tick redraws every row; the linter's `table-row-memo-props` check fails an inline function or a fresh empty literal on a row, for the reason `results-panels-memo-props` fails one on the table, and `ResultsTable.test.tsx` counts the rows each render draws, because the stabilities built outside the JSX (the hoisted empty widths, the memoized coloured group, columns and keys) are ones the lint cannot see.
- `src/components/ResultsTableRow.tsx` — one body row, ranked (the default export) or pending (`PendingRow`), each memoized (`app-memoized` holds the default export, `table-pending-row-memoized` the named one): the rank cell with its remove ×, the chart checkbox, and every cell's markup and links, each cell a component. It also owns `FireClock`, the wildfire cells' shared 400 ms clock, which reaches the cells through a context rather than a row prop so a tick redraws the wildfire cells and no row. Apart from the table because a report can hold a thousand rows and most changes touch few of them. Every prop is a primitive, a value the table memoizes, or a stable callback. `sized` from `sizedCell.tsx` wraps every cell, so the body and the header read one set of widths
- `src/components/ResultsTableHeader.tsx` — the results table's header row, and the markup of every gesture on it: the sort click and arrow, the resize handle, the chart-all box (`SelectAllCell`) and the drag ghost and insert line (`DragOverlay`, portalled to the body). Apart from the body because none of it reads a row, and memoized on its own (the `app-memoized` check holds it) so the body's re-renders do not redraw it; `ResultsTable` memoizes the columns and the chartable rows it hands over for the same reason. Every header CLICK sorts the rows on screen in place and nothing more: the panel's Ranking control is the only thing that re-ranks the field, reorders the column groups, or moves the shading (#242 review). The display order is `App.tsx` state (`detailSort`) so the CSV export can leave in it. A header DRAG is the one other thing a header does, and it moves the column rather than the rows; the two are told apart by distance and by hold, never by which of them fired first, because a tap must still sort. The gestures themselves are `useColumnDrag` and `useColumnResize`. The KEYBOARD route to the sort is on the same cell (#496): each sortable `th` is `tabIndex={0}` and sorts on Enter or Space through `handleSortKey`, which calls the sort directly rather than through the drag's click guard, prevents Space's scroll, and ignores a key repeat. It is a key handler on the cell rather than a `<button>` inside it because every pointer gesture is wired to the cell and reads its DOM (the drag measures the cell's row, auto-fit the `sized` wrapper directly under it, and a `div` wrapper is not valid inside a button), so the pointer paths stay exactly as they were; the `column-drag-header` check requires the tab stop and both keys. Every sortable header's `aria-describedby` names ONE `SR_ONLY` copy of the approved hint `Press Enter or Space to sort.`, held in the aria-hidden filler cell (a reference resolves through aria-hidden, and a cell of its own would be a column); `disabled-reason-twin` holds the pairing here as it does in `App.tsx`. Its ring is `FOCUS_RING_INSET`, because an outer ring on a sticky header is clipped by the scroll box and lands on the first row.
- `src/components/sizedCell.tsx` — `sized`, the wrapper every results-table cell renders in, header and body alike. Sized, it pins the cell's content box to the chosen width and clips; unsized it is inert but still drawn, because auto-fit measures this wrapper rather than the stretched cell. Apart from both the header and the rows because both draw it, and a copy in one of them would be a column auto-fit measures differently
- `src/components/ModelPicker.tsx` — the forecast model as a button opening a listbox of all of them, in the app's one popover shell and placed by the app's one popover hook (see the bullet below), so it is portalled to `document.body` and positioned fixed like every other panel. A native `<select>` cannot do this job: choosing well means reading eight summaries against each other, a select shows one at a time, and its options cannot carry them (the shortest needs 303px of label where the control has 245px). `title` on an option is no way out either — macOS draws the list as an OS menu that renders no tooltip, and a phone has no hover. Fixed rather than absolute because `ControlPanel` is an `overflow-y-auto` column that would clip a child at the scroll boundary. It takes a `disabled` prop for the one window the model does not apply to (an archive window, #123 — a window that CROSSES the boundary keeps the picker, because its forecast half is the chosen model's), wearing `DISABLED` rather than disappearing: a control that vanishes takes its label and its last value with it, and an info line under Analyze says why it is faded (it was a `title` on the trigger until 2026-09-14, out of reach of every touch reader). It is also where the chart's model comparison is chosen (#232), and the popover is **two parts with one gesture each**. **The LIST selects**: tick a row's box or click anywhere on the row, untick to remove, and nothing on a row ranks or closes the popover. **The CHIP ROW above it ranks**, under a `Selected models` header drawn in the list header's own recipe so the popover's two blocks read as two parts of one control: one chip per selected model in the published editorial order (never the order selected), the ranking model's chip highlighted with `CHIP.active`, and a tap on any other chip's label moves the highlight to it — the `model-changed` data knob, window clamp included, with the model it replaces keeping its chip. The split is the design: one row that both selected and ranked put two gestures a few pixels apart, one of which dismissed the list under the reader's hand. A chip's × deselects it; the ranking chip has none, so unticking its ROW is how it goes, and the ranking then passes to the next chip to the right, wrapping to the first. The last selected model cannot be given up — no ×, and its row's box disabled — because a report has to come from some model, and `role="option"` carries `aria-disabled` to say so. Nothing inside the popover closes it: Escape and an outside `pointerdown` only, which is `usePopover`'s rule rather than this file's, so the Columns picker closes the same way by construction. The closed trigger reads `{label} +{n}`, the label ellipsizing rather than widening past `CONTROL_W`, because the count is the only thing on it a reader cannot otherwise see. The listbox is `aria-multiselectable` and `aria-selected` means "on the chart"; the drawn checkboxes are `aria-hidden` with `tabIndex={-1}`, because a focusable input inside a `role="option"` would be a second tab stop in a list whose whole keyboard model is one element plus `aria-activedescendant`, and Enter and Space both toggle the active row. The chip row is a `role="toolbar"` with a roving tabindex: ArrowLeft/ArrowRight/Home/End walk it (`nextToolbarIndex`, the horizontal twin of `nextActiveIndex`, separate so one arrow key moves exactly one of the two parts), Enter ranks, Delete or Backspace removes, Tab crosses to the listbox and Shift+Tab comes back. Each chip's × is a button named `Remove {label}` and deliberately out of the Tab order, since Delete already does it and a stop per chip would double what a keyboard pays to cross the row. Every decision here — which chip ranks next, the editorial order, what the last chip may do, where the keyboard lands after a removal — is `utils/modelSelection.ts`, where the node project checks every case; `ModelPicker.test.tsx` shows that the gestures reach it. The list takes the keyboard when the panel is DRAWN rather than when `open` turns true, for the reason the hook's measuring pass runs after every commit: on the first open of a session the panel exists one render later, and an `open`-keyed focus left the keyboard on the trigger. The selection itself lives in `useForecastSelection` and the link, never here
- `src/components/MapView.tsx` — the map, and wiring only: the MapLibre instance, the `load` handler that mounts every feature in one `mountFeatures` call, the camera, and the effects that hand the features props. It has **no test of its own and cannot have one**: MapLibre needs a WebGL canvas, which the DOM project's jsdom does not provide, so anything that decides something lives in a module beside it and this file calls it. `utils/drawGeometry.ts` holds the polygon's geometry and nothing else: `makeDrawData` and `ringToPts` for the drawn ring and its handles; `ringPolygon`, `moveVertex`, `removeVertex` and `insertOnSegment`, the four edits `map/drawRing.ts` makes to it; `polygonsOf` for the rings a rendered area gives up; and `bboxAreaKm2`, the port of `bbox_area_km2` in `models/common.py` formula for formula, because the browser has to block Analyze at the size the server refuses the request at (the ring's true area would be the better number and the worse gate). **`App.tsx` calls that last one, not the map.** The panel's area line is a `useMemo` over the ring App already holds, because the map can only report an area once it has loaded, so a ring restored from a link printed its point count beside a blank area line until the reader edited it (#429); the `map-view-wiring` check fails a measurement taken back in the component. `utils/mapFeatures.ts` holds the marker builders beside it, which are a different subject in a module of their own (#442). `utils/mapClick.ts` holds what one click means when several layers answer it (`resolveMapClick`, `dismissesPopups`): the component queries every clickable layer ONCE and acts on the answer, and the order — a fire over everything, then draw mode, then a marker or a basemap label over the plume under it, then the densest plume — is a test per rule rather than a comment. `utils/mapFraming.ts` holds the camera's decisions, the opening frame's restored points (`restoredPoints`) included. What this file may say is held by the linter rather than by a test, in `tools/eslint/checks/map.js`, because the file cannot be run in either Vitest project and a rule reads code rather than text: `map-view-wiring` fails any top-level function here, and the `map-*-declares` checks name the top-level functions each map module may declare, so a new plain-data helper cannot land in any of them unseen (#383). The same file names the one module each moved map helper lives in, and fails a second copy anywhere in the wiring. It also pins where the ring a `?poly=` link opens with is read: `restoredPolygonRef`, read when MapLibre fires `load` and written by `restoreRing` (empty for Clear, the ring draw mode started with for Cancel), because the `load` handler runs long after mount and a Clear pressed in between used to be undone by the hydration there (#453)
- `src/components/icons.tsx` — every glyph the app draws, one component each (#386). Nothing else under `components/` or in `App.tsx` may contain an `<svg`, and the linter's `style-own-glyphs` check fails one that does. The module owns the drawing — paths, stroke weight, viewBox, the step from the `ICON` ramp in `styles.ts`, and `aria-hidden` on every glyph, since each one stands inside a control that already carries its own `aria-label`; the call site owns only placement and colour, passed as `className`, and a height or width handed to an icon fails the same test. It replaced nineteen hand-drawn SVGs in which the close cross existed six times at three sizes and two stroke weights, two of the six announced where the other four did not, and the select arrow's path was typed out three times. The `ICON` ramp it reads is four steps and every one states the number that chose it (#436): the search magnifier folded into `control` because a 15px box centres on a half pixel in a 36 or 44px row where the row's other two glyphs sit at 16, and the two chips' remove crosses folded into one `chip` step at 12 because both chips measure exactly 24px tall and the cross's 24-unit viewBox halves onto whole pixels at 12 and not at 10. `src/iconPaths.ts` is the one shape the module does not spell for itself (#435): the map popup is an HTML string handed to `setHTML`, which Tailwind never scans and the React module cannot draw, so the link-out arrow's geometry, stroke and size live below both and `icons.tsx` and `utils/popupChrome.ts` each render it in their own syntax. It sits at `src/` beside `styles.ts` and `metrics.ts` because no util in this app imports a component. the linter's `style-popup-glyph` check fails a literal SVG tag in `popupChrome.ts` too, since the component checks read JSX and would never see one in a string there
- `src/components/TimelineTransport.tsx` — the floating play/scrub bar over the map (#121). Wiring only; every decision it looks like it is making is `utils/timeline.ts`'s, for the reason `ForecastCalendar` splits the same way. The scrubber is a real `<input type="range">` because that is what arrives knowing arrow keys, Home/End and a screen reader; suppressing the platform look then takes three declarations, one per engine (`SCRUBBER` in `styles.ts`). The axis switch wears `TRANSPORT_AXIS_ITEM` rather than the panel's `SEGMENT_ITEM`: it is the one segment whose label the design system does not choose — the right half is the ranked metric's noun — so it takes one step more inset, which is the slack a long noun needs inside `SEGMENT_FLUID`'s clip
- `src/components/MapLegend.tsx`, `src/components/LayersPopover.tsx`, `src/components/MapButtonColumn.tsx`, `src/components/AnalysisOverlay.tsx` — the map's chrome, cut out of `App.tsx` (#409), each flat in `components/` and none memoized, because nothing they draw is a row per destination. `MapLegend` is the one legend box and the stack it scrolls in (#454): `legendSection` builds every section, the metric key included, and the list is sorted by the label each section reads; it takes `useMapOverlays` and `useGridLayer` whole rather than a prop per flag, and it is a metric surface, so it sits under the metric-name ban. `LayersPopover` is the Layers button, its popover and its click-away/Escape effect, `layerRow`, `MAP_LAYERS` in alphabetical order with every row always present, and the grid's style segment and coverage slider under the grid row. `MapButtonColumn` is the top-left cluster: the search field, the Controls button while the panel is closed, and the Layers popover as its child. `AnalysisOverlay` is the loading card with its progress bar or elapsed timer and Cancel. It composes the card (`composeOverlay`) and runs the 250 ms elapsed clock itself, so a tick re-renders the card rather than the whole page (`analysis-overlay-clock`). The column roles (`MAP_COL_W`, `MAP_COL_GAP`, `MAP_EDGE`, `LEGEND_TOP`) are split across them by the `style-map-*` checks, whose counts add up to what `App.tsx` held.
- `src/components/MapStage.tsx` — the map column above the results, cut out of `App.tsx` (#409): the wrapper that publishes `--map-corner-lift`/`--map-corner-band` and `MAP_EDGE.publish`, then `AnalysisOverlay`, `MapView`, `MapLegend`, `MapButtonColumn` with `LayersPopover`, and `TimelineTransport`, with the marker scale, the search and map-click handlers and the search field's ref that only the map reads. It takes `Pick`s of the hook results App holds and hands `MapView` each member by name, so `MapView`'s memo sees the identities it saw when App rendered it (`map-stage-memo-props`); it is not memoized itself, because App hands it fresh hook results on every render. It runs no effect, and the legend renders before the button column so the Layers popover paints over it (`map-stage`).
- `src/components/ResultsSheet.tsx`, `src/components/ResultsBar.tsx`, `src/components/ResultsPanels.tsx` — the results, cut out of `App.tsx` (#409). `ResultsSheet` is the one surface docked under the map on a desktop and a sheet over it on a phone, and it owns the Columns, Models and Removed popovers' open flags and triggers, because nothing outside it opens one; it takes `useResultsView` as one object (the layout, the chart, the table's shape and the table's callbacks), and `usePresentedReport` and `useRemovals` whole. `ResultsBar` is the header: the ranked title (a metric surface, under the metric-name ban), the Table/Chart/Both segment with Both disabled rather than removed, the five links, the two collapse chevrons and the comparison wait. `ResultsPanels` is the chart panel (the lazy `TimeSeriesChart`, so recharts stays out of the entry chunk, and the chart-only legend) and the table panel, each behind its `ResizeGrip`. It is where the two memoized children render, so it hands them only the members it is given and never a value it builds; `results-panels-memo-props` holds that the way `map-stage-memo-props` holds `MapView` in `MapStage.tsx`. The one value it builds for the chart is the comparison's `ModelCompare` element, memoized on `compare.active`, `compare.shown` and `compare.paceRemainingS`; the same check fails an element built inline on either child, and `ResultsPanels.test.tsx` holds every chart and table prop's identity across renders.
- `src/components/AppDrawer.tsx` — the controls drawer around `ControlPanel`, cut out of `App.tsx` (#409): the aside that is docked on a desktop and slides over the map on a phone, its close button, and the backdrop behind it on a phone. It takes `useDrawMode`, `useDestinationInputs`, `useForecastSelection` and `useRankingKnobs` whole and hands `ControlPanel` their members. It draws the drawer it is told is open and runs no effect: closing on a committed report stays in `App.tsx`, keyed on `analysisSeq` alone, because the report is App's (`app-drawer` and `app-effect-keys` hold both halves). The Metrics table gets the selection's `panelPointSample`, never the report's.
- `src/components/ResizeGrip.tsx` — the bar between two panels and the two gestures it answers: drag to resize, double press to put that panel back (#382). One component for both of the results area's grips, which are the same affordance with different geometry behind them. **The geometry stays at the call site**: the chart grip trades against the map, the table grip against the chart in Both mode and against the map alone otherwise, and moving that in would make one grip need to know which one it is. Each instance keeps its own press clock, so a double press puts back the panel it was made on rather than both — a drag only ever moved one. The browser's `dblclick` never arrives here (the resize starts on `pointerdown`, and `preventDefault` plus the drag overlay stop the pair of clicks resolving), which is why `DOUBLE_PRESS_MS` exists at all; the move listeners go on the document, because a resize that stopped tracking when the pointer left an 8px bar would be unusable. the linter's `app-resize-grips` check fails a second spelling of either the markup or the clock
- `src/components/MapView.tsx` — the map. It constructs the MapLibre instance (the worker URL and the vendor stylesheet, through `map.css`, enter here and nowhere else) and owns what is still wired inline: the `load` handler, the ring's POINTS (`ptsRef`, which exist before the map loads, since a restored link hydrates them, and after, since Clear and Done read them), the popup board every module shares, the opening frame (`frameOpening`, called from `load` and nowhere else) and every camera move. Every feature is mounted by ONE call, `mountFeatures` in `map/features.ts`, which owns the stacking order; the effects only hand the features props, and rows that arrive before `load` are drawn when `mapReady` flips rather than held in refs. The `map-view-wiring` check in `tools/eslint/checks/map.js` fails any source, layer, listener, popup, popup ref or direct feature mount written back into this file; it listens for `load` and nothing else. It was cut into feature modules under `src/map/` in six pull requests (#410). **No ref in it mirrors a prop**: what a handler registered once on `load` needs to read is on `map/controller.ts`, and the `map-view-wiring` check fails a ref seeded from a prop (the restored ring excepted, which is not a mirror) or an effect that only copies values into refs. Almost nothing it draws is DECIDED here — the popup markup, the marker colours, the lattice and its raster, the framing predicate and where a click joins the ring are pure modules in `utils/` that arrive as strings, features and numbers — and that split is what makes them testable at all, since a test that reached into this file would be pulling a WebGL map into it, which jsdom cannot draw. Memoized like `ResultsTable` and `TimeSeriesChart`, so its props must stay stable
- `src/components/TimeSeriesChart.tsx` — the recharts line chart under the results, plus the metric select above it. It PLOTS `ChartLine`s rather than rows (`chartData.ts`): it builds one line per row it is handed and appends `extraLines`, the comparison's (destination, model) pairs, which arrive already aligned, coloured and named — so nothing past that point knows which kind it is drawing, and a comparison hands it every line and no rows at all. The rows it does get are the ones already chosen, because the table's checkbox column is the one series picker. Two things it owns that recharts does not hand over are the hover box, positioned by inverting pixels back to data values, which drops its per-line emphasis for a plain shared tooltip past the point where re-rendering every path can keep up with the pointer, and the map timeline's playhead, drawn as a reference line and moved by clicking the chart. A click is read from its own `clientX` through `pixelToTime` rather than from Recharts' `activeLabel`, because that label comes from the hover state: a touch tap sends no hover first, so the first tap had no label and each later one carried the tap before it (#517). Memoized, so its props must stay stable
- `src/components/ColumnsPicker.tsx` — the results bar's Columns popover: a checkbox row per column, portalled to `document.body` and placed by `popoverBox`, with drag-to-reorder sharing `columnDrag.ts` with the table header so one gesture means one thing in both. Its measuring pass runs after EVERY commit rather than keyed on `open`, and that is a bug it already shipped once: the trigger lives in `ResultsSheet.tsx` and only flips `open`, so an `[open]`-keyed pass ran before the element existed on the first open and the unmeasured fallback stuck for the whole of it, while every later open measured against the previous one's stale box
- `src/components/RemovedPicker.tsx` — the list behind the results bar's Removed button (#241): every ×-ed row by name, each with its own restore, plus a restore-all, so a removal is reversible for as long as it is in force rather than for the lifetime of a toast. Same portal, same placement math and same dismissal as `ColumnsPicker`, since the two are siblings on the same bar
- `src/components/ControlPanel.tsx`: the panel's frame, and the state its parts share: the header, the scrolling stack of the three sections, the footer, and every derivation more than one of them reads. That is the Analyze gate (`analyzeGate.ts` fed from the polygon, the CSV parse, the pins and the model comparison), the selected window with its source and its air-quality coverage, and the inputs `panelMessages` composes its lines from. It keeps App's one 49-field interface so App wires one component, and hands each section only the props it draws. It renders no control and no message itself: each section is its own file below, and the footer is the one place a message can appear. It also fires a link's run on open (`autoAnalyze`, `onAutoAnalyze`) from an effect keyed on the gate, because the gate is computed here and lifting it for one boolean would move a dozen inputs into App
- `src/components/DestinationsSection.tsx`: the panel's first section, the three ways to name destinations (the map, a drawn polygon, pasted coordinates). It owns the draw counter, the only panel text coloured by `STATUS` (pinned at six uses by the linter's `style-draw-counter` check), the destination-type checkboxes, the unnamed-peaks knob that ticks Peaks with it, and the paste-versus-typing flag that decides whether a CSV change frames the map. The point count and the area verdict arrive as props rather than being derived again, so the counter and the Analyze gate cannot disagree
- `src/components/ForecastSection.tsx`: the panel's second section: the model picker beside its label and the calendar under it, and the `band` the calendar is drawn over (memoized, because the month grid hangs off it). It draws no message: every sentence about the window is a line in `panelMessages.ts`
- `src/components/MetricsTable.tsx`: the panel's third section, the ranking and the bounds in one grid (#341): the direction segment, the results cap, one row per ranked metric (radio, aggregate dropdown, floor and ceiling boxes), and Clear filters. It owns the tables behind those rows (`BOUNDS`, `EDGES`, `BOX_PLACEHOLDER`, the one box shape) and all four of the panel's approved tooltips, which is why `APPROVED_TOOLTIPS` keys them to this file. Every control here is a presentation knob, so nothing in it needs an Analyze
- `src/components/PanelFooter.tsx`: the Analyze button, the one notice block under it, and the two document links. `FooterNotice` is declared and rendered here and nowhere else, which is how the linter's `style-footer-notice` checks hold the one-block rule across the panel's files, and the dismissal ledger lives here because a dismissal is presentation: it prunes by `notices.ts`'s rules against whatever keys the current message list carries
- `src/components/WelcomeModal.tsx` — the first-run dialog: five steps walking the panel top to bottom, then Analyze and what follows it. Every step is named for the panel section it describes, so a renamed section renames its step, and the whole Metrics table is covered in one step because a step per question would push the dialog past the height it can hold without scrolling
- `src/components/SafetyNotice.tsx` — the one sentence saying this is a planning aid rather than a safety tool, returned as a fragment so each caller supplies its own paragraph and `PROSE` role. It is shared because the welcome dialog is exactly the wrong place for it to live alone: that dialog is dismissed once and remembered forever, so the people with the most trips behind them are the least likely to have seen it recently. `/terms` is where a link can reach it
- `src/components/PageShell.tsx` — the frame all three standalone pages wear, and the anchored `Section` inside it, so a `/terms#license` link lands somewhere useful when the page gets cited in an issue. None of the three is the app, so none gets the map's chrome, but they are reading surfaces in the sense the dialogs are and take the same card and `PROSE` tier rather than inventing a third look. No router and no shared state with `App.tsx`: these are separate Vite entries, and importing anything from the map's tree would pull maplibre into a bundle that renders text
- `src/components/PrivacyPage.tsx` — the public privacy policy on its own URL, because the systems that ask for one ask for it separately from the terms. It is a promise to users rather than documentation, and it goes stale from behavior changes made in files nobody thinks to connect to it: #169 added rate limiting keyed on client address, which quietly falsified a claim here until it was rewritten. `legal.test.ts` pins the claims that have already been wrong once
- `src/components/TermsPage.tsx` — the public terms on their own URL, for the same reason: an app store or a data provider wants a privacy link and a terms link, not one page covering both. It carries the license (PolyForm Noncommercial, with commercial use by arrangement), the shared safety notice, the provider list and the contact block
- `src/components/NotFoundPage.tsx` — the page Starlette serves for any static path that does not resolve, so a mistyped URL is a page rather than the raw JSON body of an HTTP exception. Nothing on it explains the miss: a 404 cannot tell a typo from a dead link from a path that never existed, so any explanation is a guess, and the ones it used to offer sent people somewhere they had not asked to go. Paths under `/api` keep their JSON, from `notfound.py`
- `src/components/ErrorBoundary.tsx`: what a page shows when a render throws, which is one approved sentence and a Try again button that mounts the same children again in place, on `SURFACE_PAGE` so it needs nothing from the tree that just failed. All four entries (`main.tsx`, `privacy.tsx`, `terms.tsx`, `notfound.tsx`) render inside it, because React unmounts everything under a throw that nothing catches and leaves the root empty. A class, since React has no hook that catches a render error. It writes the error and the component stack to `console.error` and nowhere else, since the browser has no telemetry endpoint, and it imports only `styles.ts`, so the text pages that wear it do not pull in the map. the linter's `entries-inside-boundary` check pins the wiring of every entry, and `ErrorBoundary.test.tsx` proves the catch and the retry in a real render
- `src/components/ContactBody.tsx` — the contact block both document pages carry, because each is a page someone lands on alone: a privacy question and a licensing question arrive at the same address, and neither reader should have to guess which page holds the details
- `src/components/DataSourceList.tsx` — the provider list both document pages render, and the LIST only: the lead-in paragraph stays at each call site, because `/privacy` cares that these are third parties a request reaches and `/terms` cares whose license covers what comes back. Sharing the list is what stops a provider added to `dataSources.ts` appearing on one page and not the other.
