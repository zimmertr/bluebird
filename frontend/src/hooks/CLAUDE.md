# Frontend layout: `src/hooks/`

- `src/hooks/useColumnDrag.ts` — a press on a header that becomes a column move: the carried column and the insert line as state, the document listeners (a drag leaves the cell it started in on its first frame), the commit on release only when the column lands somewhere new, and `endedDrag`, which lets the header ignore the click that ends a drag until the next tick. Apart from the resize because the two share no state: this changes the column order, that a width. `begin` is stable while the columns and `onColumnMove` are
- `src/hooks/useColumnResize.ts` — a column's width, by dragging the header's edge (`begin`, measured from the width at the press, spreading the widths on screen each frame) or by double-clicking it (`fit`). The handle's press stops propagation, so it is never also a sort or a move (the `column-resize-handle` check). The latest widths ride a ref updated in a layout effect, read only by the pointer listeners
- `src/hooks/useAnalyze.ts` — one Analyze click, composed: the run in flight (`useAnalysisRun`), the report it commits (`useAnalysisReport`), and the work between them (`utils/analysisPipeline.ts`). What stays here is what spans runs: the forecasts the next run may reuse, set only once a run has committed, and the request `retry` repeats. The returned object is the API `App.tsx` destructures, and `useAnalyze.test.tsx` pins its names and their order. The one path since #240: an unreachable Open-Meteo fails the analysis with its own message rather than rerouting through the server's shared quota. Its public types (`Progress`, `Refusal`, `AnalyzedView`, `AnalyzeOptions`) live in `analyzeTypes.ts` and are re-exported here
- `src/hooks/useAnalysisRun.ts` — the analysis in flight: `loading`, the status line, progress, the pace countdown, cancel, and the error or refusal a failed run shows. Apart from the report because the two reset on different events: this clears when a run starts (which is what re-arms a dismissed notice), the report only when a new one commits. Which box a failure lands in is `utils/analysisFailure.ts`
- `src/hooks/useAnalysisReport.ts` — the committed report: `response`, the full field (`universe`), the `analyzed` snapshot, `arriving`, `analysisSeq`, and the candidate field published for the wildfire check with its own `fireSeq`. Apart from the run because it outlives one: a cancel or a failure leaves it standing. `analysisSeq` moves on a full commit only, never on a partial one
- `src/hooks/analyzeTypes.ts` — the shapes `useAnalyze` hands its callers: a run's progress, a refusal, the `AnalyzedView` snapshot a report was analyzed under (it composes `present.ts`' `AnalyzedSnapshot` rather than restating it), and the options a run records. Types only, apart from the hook so a component or a pure module can name them without reading the hook; `analyzeTypes.test.ts` holds them to the hook's re-exports at the type level
- `src/hooks/useCapabilities.ts`: the deployment's published limits from `GET /api/capabilities`, with compiled fallbacks held only until it answers (#152, #393). `parseCapabilities` maps the body per field, so an older build that publishes a subset leaves each missing limit on its fallback. The hook also says when the fetch has `settled` (answered or failed; an abort is neither), kept off `Capabilities` because the parser and the fixtures have no fetch to settle. A link's run on open waits for it, because the restored model and results cap are clamped against the live limits; App then waits one commit more, because those clamps land in effects whose state reaches the next render
- `src/hooks/useRankingKnobs.ts` — the presentation knobs: the ranking, its direction, each metric row's aggregate, the forecast bounds and the results cap, plus `liveKnobs`, the one memoized value `present.ts` re-derives the table from. Its own hook because these knobs apply live and never reach the data side of a request (#188), and because `liveKnobs` must keep its identity across a render that changed no knob or the table re-derives for nothing. It owns the limit re-clamp once `/api/capabilities` lands (only ever lowers) and `clearFilters`, which clears the bounds and the cap together because they are one column of the Metrics table (#341)
- `src/hooks/useForecastGrid.ts` — the fetch for the `utils/forecastGrid.ts` overlay: keyed on `(enabled, analysisSeq, pitchKm)`, best-effort, and null-universe (no committed analysis yet) means no grid. The toggle is the spend gate and leaving it on is standing consent for the next analysis. Weather goes out in `PAINT_CHUNK`-sized chunks run **one after another**, each painted as it lands, so the field fills in rather than appearing after the twelfth batch; the chunks are sequential precisely so the total in flight stays where the pacer expects it. **AQI is never awaited before painting** — it rides alongside and repaints what is already drawn, because awaiting it meant a temperature field sat invisible behind 600 air-quality samples nobody had asked to see. The hook also surfaces `paceRemainingS` from `usePacedFetch`, which is what lets the grid's **own legend box** say why nothing has appeared yet (`gridLegendLine` in `forecastGrid.ts`; it is a box of its own like every other overlay's, because appending the line to the metric legend made that box two things at once — a key to what the colours mean and a status line about one layer, when those colours are shared with the markers rather than owned by the grid): the grid inherits the quota debt of the analysis before it, so after a large one it is minutes before the first samples land and silence reads as broken
- `src/hooks/useChartBox.ts` — the results table's chart checkbox handlers: the shift-click range select, and a plain click's toggle. Both keep one identity for the table's life and read the latest rows and callbacks through a ref, because every row is memoized on them. Apart from the table so the range logic has a hook test of its own (`useChartBox.test.tsx`: the run, a clear, a plain click after a shift-click, a run with no series, and the order after a sort)
- `src/hooks/useChartSelection.ts` — which destinations are charted, the colour each one keeps, and the active metric. A colour is allocated once per coordinate key, from the app's one allocator in `chartColors.ts`, and never reassigned, which is what lets a searched place wear before an analysis the colour its line draws in after, wherever it ends up ranking. `colorByKey` doubles as the "ever charted" memory, so a box the reader deliberately unticked is never re-ticked by a later report. The debut scan keys on the SET's identity rather than on the array holding it, because the caller's candidate list is rebuilt on every keystroke in the coordinates box and on every live knob change (#185)
- `src/hooks/useSearchedPlaces.ts` — the places registered by name, one of the three destination inputs. Nothing here fetches: searching registers the place, and its forecast arrives with the next Analyze, which is where the spend boundary is. Re-searching the same feature refreshes it in place rather than adding a second row
- `src/hooks/useResultsLayout.ts` — where the results stand and how tall they are, cut out of `App.tsx` (#409): the Table/Chart/Both mode and its one stored press, the two panel heights and the handlers of both grips, the collapse chevron, the drag scrim flag, the live viewport height, the measured sheet and the lift, corner lift and camera padding read from it. State and wiring only: every number it decides with is a pure function in `utils/layout.ts` or `utils/resultsSheet.ts`, and the grip's markup and double-press clock are `ResizeGrip`'s. `DEFAULT_PANEL_HEIGHT` lives here, and `resultsSheet.test.ts` reads it as text against the arithmetic. It takes the stored mode as an argument rather than reading `viewPrefs` again, because `App.tsx` reads the stored view once and hands the table the rest. The sheet measurement keeps its layout effect with no dependency list: the mode switch, the chevron, a drag and a rotation all re-render the app, and a list would miss one of them. The linter's `results-layout-hook` check holds the floors, the defaults, the one write and that effect
- `src/hooks/useDestinationInputs.ts` — the three ways a reader names destinations, cut out of `App.tsx` (#409): the polygon and its area, the kinds it looks for and the unnamed-peaks switch, the pasted coordinates and their parse, and the searched places with their one restore from the link. One hook because the two values read across them need all three: `destinationScope`, the authored inputs a removal is recorded under, and `destinationNamed`, the fact the results panel opens on. That fact is a boolean on purpose: `csvRows` is a new array per keystroke, and an effect keyed on it is React error #185 (#185), which the linter's `destination-inputs-hook` and `app-effect-keys` checks both refuse. The area is derived from the ring rather than reported by the map, so a ring restored from a link has an area before the map loads (#429). Registering a place is `useRemovals`', because it also drops a stale removal, which is state this hook does not own
- `src/hooks/useDrawMode.ts` — draw mode (#118): whether a map click adds a vertex, the vertex count, and every way in and out of the mode — Draw or Edit (which frames the ring and, on a phone, closes the drawer that would cover it), Done, Cancel, Clear, and Enter and Escape. It owns the one copy of the ring a Cancel can put back (#478), because the map reports every edit as it happens and nothing else keeps the ring as it stood. The count is seeded from a restored ring so Analyze unlocks before the map loads. The keys stand down while focus is in a text or number field, where they belong to the field
- `src/hooks/useRemovals.ts` — the rows a reader ×-removed (#241) and every way one comes back, cut out of `App.tsx` (#409): the × itself, restore and restore all, registering a named place (which drops a stale removal of the same spot), and the clear an Analyze asks for when the discovery scope moved. The decisions are `utils/removals.ts`'s; this hook holds the map and knows which rows the browser still holds, which is what decides whether a restore unhides a row or re-registers a place. It hands out two key sets on purpose: every key for the report and the refresh echo, which are snapshots of one analysis, and only the keys under the live scope for the pending preview (#158)
- `src/hooks/usePresentedReport.ts` — the report as the reader sees it, cut out of `App.tsx` (#409): the ranked rows from `presentResults` with their remembered identities put back (a refresh echo comes back as `custom` with no OSM id), the pending destinations, the window caption, the detail-column sort (#125) and the bar's count and empty-table reason. One hook because every one of them reads the same displayed rows, so the table, the markers and the count cannot disagree. It returns `results` in ranking order; the detail sort is applied by the caller's `tableRows`, so the markers never follow it
- `src/hooks/useAnalyzeCommand.ts` — the Analyze button, cut out of `App.tsx` (#409): the side effects of one click in the order they must run (end drawing, clear removals for a new scope, open the results before the await so arriving rows show, record the discovery before or after the run) and the one piece of state that outlives a click, the discovery record a later Analyze reads to decide whether it may refresh. Apart from `useAnalyze`, which owns the run and the report; this hook only decides when to start one. `handleAnalyze` is a plain function, because `analyze` is new on every render and a memo on it would never hold
- `src/hooks/useMapOverlays.ts` — the map's overlay switches (wildfires, radar, smoke, snow depth, the forecast grid) and the forecast player's, cut out of `App.tsx` (#409), with `playerShown`: the reader's decision where there is one, the device's default (on at a desktop width, off on a phone) where it is null. None is a knob, so none reaches `commitNeeded`. Its own hook because the map, the Layers popover, the legend and the timeline all read the switches and none of them owns them
- `src/hooks/useTimeline.ts` — the map timeline's state and interval (#121), cut out of `App.tsx` (#409): the chosen axis, one playhead per axis, play and pause, the readout, and the seek a chart click makes. Every decision is `utils/timeline.ts`'s. It owns `forecastTimes`, memoized with a hoisted empty grid (`NO_TIMES`), because the memoized map and chart take it and the seek is keyed on it. The playhead resets on `analysisSeq` alone, never on the times array, which a live knob renews; the linter's `timeline-hook` check holds that and the effect count
- `src/hooks/useGridLayer.ts` — the forecast grid layer's state, cut out of `App.tsx` (#409): the style, the committed coverage and the drag draft that commits only on release, whether the layer may draw (`gridAllowed` of the analyzed snapshot, once) and whether it is in effect (`gridOn`), the fetch it feeds `useForecastGrid`, and the flags the legend reads. Every fetch input comes from the `analyzed` snapshot, so a panel model change moves neither the grid's model nor its pitch; only the slider's quoted kilometres read the panel's model before a report exists. The Layers list is `LayersPopover.tsx`'s and reads `gridAvailable` from here
- `src/hooks/useChartCompare.ts` — the comparison chart's wiring, cut out of `App.tsx` (#409): the charted set (`useChartSelection`) over the displayed rows plus the pending ones, the compare fetch (`useModelCompare`), the hidden models and their prune when the panel deselects one, the table's per-model rows flag (`comparingRows`), and the comparison wait the results bar says when the chart cannot. It owns the one decision neither child hook can make: a colour per (destination, model) pair, allocated before the lines are composed and seeded so the ranking model's line wears the destination's own colour (`pairKeysFor`, `seedPairColors` in `utils/modelCompare.ts`). `rowChartColor` keys on `chart.colorFor`, never on the `chart` object, which is new every render; the linter's `chart-compare-hook` check holds that and the two effects
- `src/hooks/useTableView.ts` — the results table's shape, cut out of `App.tsx` (#409): the reader's column answers (visibility, the three-valued Model column, the dragged order) and the one effect that stores them through `viewPrefs.ts`, the session's column widths and their reset when a point-sample flip relabels the metric columns, the rows under a comparison (`modelRowsFor`) in the header sort's order, the partial-coverage note, the chart-only legend's chips, the column lists the table and the Columns picker draw, and the CSV download. The dragged order is dropped when the ranking changes and never on mount: `rankedOnce` and its `[sortBy]` effect are one mechanism and live together, and the linter's `table-view-hook` check holds that, the width reset, the single store and the three-effect count. It takes App's one `readViewPrefs` result rather than reading storage again.
- `src/hooks/useUrlSync.ts` — the address bar as a copy of the panel, cut out of `App.tsx` (#409), last of the split because it reads state from every other hook: one `debounceUrlWrite` writer for the component's lifetime, the effect that queues a write when the shared state changes (and cancels a queued one when the state comes back to what the bar already shows), and the unmount flush. It returns the writer, whose `flush` the link's run on open uses to strip `analyze=1` now. The effect's 21-entry dependency list and its suppression moved verbatim: the list leaves out `forecastModel` and `defaultForecastModel`, which is #292's bug rather than this file's. The linter's `url-sync-hook` holds the two effects, the list's length with `writeUrl` last, and no flush inside the sync effect; `app-url-writes` holds the one history write.
- `src/hooks/useResultsView.ts` — the results sheet's view, cut out of `App.tsx` (#409): whether the sheet shows (`showTable`), then `useResultsLayout`, `useChartCompare` and `useTableView` in the order App held them (the chart hears the layout's `chartShowing`, the table hears the chart's comparison), and the table's three callbacks that reach the map (remove a pending destination, fly to a row, fly to a pending point), each a `useCallback` for the memoized rows. One call so `ResultsSheet` takes one object. It runs no effect of its own; each hook it calls keeps its own count and check. The linter's `results-view-hook` holds the order and the callbacks.
- `src/hooks/useRunOnOpen.ts` — the link's run on open (`analyze=1`, #511), cut out of `App.tsx` (#409): the flag read once at mount, `capsApplied` one commit behind the live limits so the run reads the clamped model and results cap, and `runAutoAnalyze`, which clears the flag, flushes the URL writer and then clicks Analyze. It takes the flush and the click as plain functions, so its inputs name no other hook's return type. `useRunOnOpen.test.tsx` pins the one-commit delay; the linter's `run-on-open-hook` holds the one effect and the flush before the run.
- `src/hooks/useIsDesktop.ts` — Tailwind's `lg` breakpoint as a value JavaScript can read. The layout itself is driven by `lg:` classes, but a few decisions need the breakpoint too: the mouse-only resize drag, the inline panel heights, and the docked-versus-sheet branches in the results arithmetic
- `src/hooks/useDialog.ts` — dialog accessibility in one hook: focus moves into the panel on open and back where it was on close, Escape and Enter close, and Tab cycles inside the panel instead of escaping to the page behind the backdrop. Enter is GUARDED rather than unconditional, because the hook is shared and the next dialog may not be read-only: an element that already does something with Enter keeps it, and what is left is Enter pressed against the panel or its prose, which is the "I have read this" gesture
- `src/hooks/usePreview.ts` — where the contents of `components/PreviewBanner.tsx` come from: `GET /api/config` at mount. Runtime rather than baked in, because the SPA is built once and then deployed to many environments, so the image cannot carry the answer
- `src/hooks/useColumnDrag.test.tsx`: the carry, the insert line and the move on release; no move over its own column; no drag for a finger that has not held, and a drag once it has; the ending click swallowed until the next tick; the listeners detached on release, on cancel and on unmount; stable callbacks and the returned names in order
- `src/hooks/useColumnResize.test.tsx`: each frame measured from the start width (or the header's content box when the column has none) while the widths on screen are kept, the listeners detached on release, on cancel and on unmount, the fit to the longest cell, stable callbacks, and the returned names in order
- `src/hooks/useAnalyze.test.tsx`: the whole hook with the ranking mocked: reuse at +14 minutes, none at +15 or at +16 from the first fetch, nothing held after a failed run or a reset, one commit and one fire field per analysis, the last report kept through a failure, the snow date of each run's own discovery, a retry repeating the recorded discovery, the seed label for a ring and for a custom list, reset clearing the error and the refusal, rows that arrived before a failure left on screen and no longer arriving, and the returned names in order
- `src/hooks/useAnalysisRun.test.tsx`: the seed and the status clearing when a run ends, progress, the error and refusal boxes, cancel aborting the signal, and the event states cleared as the next run starts
- `src/hooks/useAnalysisReport.test.tsx`: a commit counts, a partial one arrives without counting, the fire sequence moves on publish only, and clear keeps the counters
