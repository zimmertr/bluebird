# Frontend layout: `src/hooks/`

- `src/hooks/useExit.ts` — whether a card that has just closed is still on its way out (#714): the menus `usePopover` places, the Layers card and the legend card. It keeps the card mounted for its own computed transition after a close, so the card leaves the way `MOTION.menu` brought it in, and reads the time off the card's computed style rather than copying 150ms, so `motion-reduce:` and jsdom (which has no stylesheet) both make it instant. The closing flag is derived during render, so the commit that closes is the one that marks it closing, and a reopen during the exit clears it. A keyboard inside the card goes back to `returnRef` as the exit starts, because `useTakeOrphanedFocus` looks on the close's frame and the card has not unmounted then. Separate from `usePopover` because the two map cards stand in place and are not placed by it. Record: [0201](../../../docs/decisions/0201-one-menu-for-every-trigger.md)
- `src/hooks/useFocusHandoff.ts` — where the keyboard goes when the control holding it goes away (#576): unmounted, disabled, or inside the `inert` drawer, all of which park the focus on `<body>` so the next Tab starts from the top of the page. One rule, the control that REPLACES the pressed one takes the focus, as `takeOrphanedFocus` (a ref callback, for a control that mounts in its place: Draw polygon's Cancel, the overlay's Cancel) and `useTakeOrphanedFocus` (for one that was there all along and becomes the right place: Analyze as a run ends, the drawer's Close button as it opens, a popover's trigger as it closes, Layers as its menu shuts, the map's summary chip as the panel or the Controls sheet shuts). The focus counts as lost only when the element that last had it can no longer hold it and nothing usable holds it instead, which needs that element, so the module keeps it from one `focusin` listener: `<body>` alone cannot tell a reader whose button vanished from one who clicked the map or a page nobody has touched, and stealing the focus in either would be worse than the bug. Record: [0089](../../../docs/decisions/0089-focus-follows-the-replacement.md) The handoff focuses with `preventScroll` (#696): a phone's Controls sheet takes it for its Done button in the commit that starts the sheet sliding up from below the screen, and a scrolling focus carried the app's column 465px up and back down with the slide at the end of the tutorial.
- `src/hooks/useColumnDrag.ts` — a press on a header that becomes a column move: the carried column and the insert line as state, the document listeners (a drag leaves the cell it started in on its first frame), the commit on release only when the column lands somewhere new, and `endedDrag`, which lets the header ignore the click that ends a drag until the next tick. Apart from the resize because the two share no state: this changes the column order, that a width. `begin` is stable while the columns and `onColumnMove` are
- `src/hooks/useColumnResize.ts` — a column's width, by dragging the header's edge (`begin`, measured from the width at the press, spreading the widths on screen each frame) or by double-clicking it (`fit`). The handle's press stops propagation, so it is never also a sort or a move (the `column-resize-handle` check). The latest widths ride a ref updated in a layout effect, read only by the pointer listeners
- `src/hooks/useAnalyze.ts` — one Analyze click, composed: the run in flight (`useAnalysisRun`), the report it commits (`useAnalysisReport`), and the work between them (`utils/analysisPipeline.ts`). What stays here is what spans runs: the forecasts the next run may reuse, set only once a run has committed, and `failedView`, the snapshot of the run that last failed, which the Analyze button's word is read against (#736, `retryStands`); a failure puts the committed report back untouched, so that report's snapshot cannot say what failed. It also holds the field a polygon run found (`pendingField`, #782) from the moment discovery answers: a commit, a cancel, the next run and a reset drop it, a failure keeps it as pending rows beside the report put back (`onFailure` is told the kind), and the next run whose ring, kinds and list match (`foundKey`) hands it to the pipeline as `found` in place of discovery. Record: [0204](../../../docs/decisions/0204-a-failed-polygon-run-keeps-its-found-field.md) `analyze` resolves true only when the run committed, and calls the click's `onCommit` in the commit's own render, so the bookkeeping is the commit's and not the click's (#560). Record: [0093](../../../docs/decisions/0093-uncommitted-run-changes-nothing.md) The pod's call still out when the report commits (`late`, #673) lands on it afterwards: the hook patches the committed report and the held field with the rows it changed, under a run counter that drops an answer arriving after the next Analyze or a reset, and `pendingHeights` names the rows still without an elevation meanwhile; `placeHeld` lands the paste-time lookup's answers the same way, reducing the held columns through `placeRows`, and the commit itself calls it with whatever that lookup learned while the run was fetching (`identity.latest()` over `answered`), because an answer that landed mid-run reached no report. Record: [0114](../../../docs/decisions/0114-report-lands-before-the-elevation-lookup.md) The returned object is the API `App.tsx` destructures, by name, so the typecheck holds its members. The one path since #240: an unreachable Open-Meteo fails the analysis with its own message rather than rerouting through the server's shared quota. Its public types (`Progress`, `Refusal`, `AnalyzedView`, `AnalyzeOptions`) live in `analyzeTypes.ts` and are re-exported here
- `src/hooks/useAnalysisRun.ts` — the analysis in flight: `loading`, the status line, progress, the pace countdown, cancel, and the error or refusal a failed run shows. `run` resolves true only when its body finished, which is how the click tells a commit from a cancel or a failure (#560). Apart from the report because the two reset on different events: this clears when a run starts, the report only when a new one commits. `dismissEvent` clears the error or the refusal when the reader dismisses its line (#736): an event is state, so its dismissal clears it, the footer's ledger keeps the derived lines only, and the Analyze button that read `Try again` off the error reads `Analyze` again at once. Which box a failure lands in is `utils/analysisFailure.ts`
- `src/hooks/useAnalysisReport.ts` — the committed report: `response`, the full field (`universe`), the `analyzed` snapshot, `arriving`, `analysisSeq`, and the candidate field published for the wildfire check with its own `fireSeq`, which the closure check reads too (#550: one lookup per analysis over the same candidates, so one publisher). Apart from the run because it outlives one. It keeps the last committed report apart from the state partial rows overwrite, and a run that does not commit puts it back exactly (`discard`): the same `response`, `universe` and `analyzed` objects and the candidate field that report published, its partial rows discarded, or the no-report state when there was none (#560). Record: [0093](../../../docs/decisions/0093-uncommitted-run-changes-nothing.md). `analysisSeq` moves on a full commit only, never on a partial one and never on a discard, so nothing keyed on it fires for a run that changed nothing. `discardSeq` moves on a discard of a run that had shown partial rows and on nothing else, for the one surface that must react to those rows going: the map's popups (`useClosePopupsOnCommit`). `patch` (#673) lands a lookup's late answer on the committed report in place, each changed row replacing the committed row at its coordinate in the universe, the response and what a discard puts back, with no sequence moved, because the report is the one that committed with some of its numbers filled in; `pendingHeights` is the set of rows still without an elevation, set by `commit`, narrowed by `patch` to the rows it did not place (answers land a few rows at a time: the pod's lookup, then its one retry) and cleared by `settleHeights` and `clear`; `App.tsx` intersects it with the lookup's `inquiring` set, so a cell ticks only while an answer may still come
- `src/hooks/analyzeTypes.ts` — the shapes `useAnalyze` hands its callers: a run's progress, a refusal, the `AnalyzedView` snapshot a report was analyzed under (it composes `present.ts`' `AnalyzedSnapshot` rather than restating it), and the options a run records. Types only, apart from the hook so a component or a pure module can name them without reading the hook; `analyzeTypes.test.ts` holds them to the hook's re-exports at the type level
- `src/hooks/useCapabilities.ts`: the deployment's published limits from `GET /api/capabilities`, with compiled fallbacks held only until it answers (#152, #393). `parseCapabilities` maps the body per field, so an older build that publishes a subset leaves each missing limit on its fallback. The hook also says when the fetch has `settled` (answered or failed; an abort is neither), kept off `Capabilities` because the parser and the fixtures have no fetch to settle. A link's run on open waits for it, because the restored model and results cap are clamped against the live limits; App then waits one commit more, because those clamps land in effects whose state reaches the next render. `publishesModels` tells the deployment's own model list from the stand-in by the fallback array's identity, because only a published list can say a link's model is not offered; a failed fetch or a body with no list keeps the stand-in for good Since #676 it also parses `coverage`, the three snapshot layers' outlines, keeping each only when it is a MultiPolygon, because a renamed or malformed one must grey nothing rather than everything
- `src/hooks/useRankingKnobs.ts` — the presentation knobs: the ranking, its direction, each metric row's aggregate, the forecast bounds and the results cap, plus `liveKnobs`, the one memoized value `present.ts` re-derives the table from. Its own hook because these knobs apply live and never reach the data side of a request (#188), and because `liveKnobs` must keep its identity across a render that changed no knob or the table re-derives for nothing. It owns the limit re-clamp once `/api/capabilities` lands (only ever lowers) and `clearFilters`, which clears the bounds and the cap together because they are one column of the Metrics table (#341)
- `src/hooks/useForecastGrid.ts` — the fetch for the `utils/forecastGrid/forecastGrid.ts` overlay: keyed on `(enabled, analysisSeq, pitchKm)`, best-effort, fetching nothing while a run's rows arrive, because a lattice fetched for an arriving snapshot would be served under the report a cancel puts back (#560), and null-universe (no committed analysis yet) means no grid. The toggle is the spend gate and leaving it on is standing consent for the next analysis. Weather goes out in `PAINT_CHUNK`-sized chunks run **one after another**, each painted as it lands, so the field fills in rather than appearing after the twelfth batch; the chunks are sequential precisely so the total in flight stays where the pacer expects it. **AQI is never awaited before painting** — it rides alongside and repaints what is already drawn, because awaiting it meant a temperature field sat invisible behind 600 air-quality samples nobody had asked to see. The hook also surfaces `paceRemainingS` from `usePacedFetch`, which is what lets the grid's **own legend box** say why nothing has appeared yet (`gridLegendLine` in `forecastGrid.ts`; it is a box of its own like every other overlay's, because appending the line to the metric legend made that box two things at once — a key to what the colours mean and a status line about one layer, when those colours are shared with the markers rather than owned by the grid): the grid inherits the quota debt of the analysis before it, so after a large one it is minutes before the first samples land and silence reads as broken
- `src/hooks/useChartBox.ts` — the results table's chart checkbox handlers: the shift-click range select, and a plain click's toggle. Both keep one identity for the table's life and read the latest rows and callbacks through a ref, because every row is memoized on them. Apart from the table so the range logic has a hook test of its own (`useChartBox.test.tsx`: the run, a clear, a plain click after a shift-click, a run with no series, and the order after a sort)
- `src/hooks/useChartSelection.ts` — which destinations are charted, the colour each one keeps, and the active metric. A colour is allocated once per coordinate key, from the app's one allocator in `chartColors.ts`, and never reassigned, which is what lets a searched place wear before an analysis the colour its line draws in after, wherever it ends up ranking. `colorByKey` doubles as the "ever charted" memory, so a box the reader deliberately unticked is never re-ticked by a later report. The debut scan keys on the SET's identity rather than on the array holding it, because the caller's candidate list is rebuilt on every keystroke in the coordinates box and on every live knob change (#185) It reads each held slot through `lineColor`, which carries both themes' shades, so a switch recolours the charted lines without reallocating them or re-rendering anything that draws them (#706, #786). Record: [0211](../../../docs/decisions/0211-theme-switch-renders-nothing.md)
- `src/hooks/useSearchedPlaces.ts` — the places registered by name, one of the three destination inputs. Nothing here fetches: searching registers the place, and its forecast arrives with the next Analyze, which is where the spend boundary is. Re-searching the same feature refreshes it in place rather than adding a second row

It takes the stored mode as an argument rather than reading `viewPrefs` again, because `App.tsx` reads the stored view once and hands the table the rest. The sheet measurement keeps its layout effect with no dependency list: the mode switch, the chevron, a drag and a rotation all re-render the app, and a list would miss one of them. Record: [0154](../../../docs/decisions/0154-phone-readout-rises-into-the-sheet.md) A phone's Chart alone rests at that stop too (`chartLifted`): a render-time hold over the stored heights, so Table comes back at its own height, released by a drag on the Chart (`chartDragged`, forgotten when Chart is left and cleared by a double press), with the camera padded for the full sheet while it holds.
