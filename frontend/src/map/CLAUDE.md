# Frontend layout: `src/map/`

- `src/map/basemap.ts` — the map's module-level helpers, cut out of `MapView.tsx` unchanged (#410): `STYLE`, the OpenFreeMap style URL `coldLoad.test.ts` checks the preconnect hints against; `enhanceBasemap`, which patches the loaded style with the trails and the clickable peaks and lakes, each label with its hidden glow directly beneath it, all under the style's first label; `glowTwin` and `poiLabelLayout`, the specs it builds from; `lakeAnchor`, where a clicked lake becomes a coordinate; the POI glow's canvas image; and `setSource`. Separate because none of them needs the component: each is handed a map, a canvas or an event. It imports MapLibre for its TYPES only, which is what lets `basemap.test.ts` run it in node against a stub map and pin the layer order `enhanceBasemap` adds, the filter it composes onto the style's water labels, and the `map-basemap-declares` and `map-basemap-layers` checks hold the file's allowed top-level functions and what it must say about the clickable peaks and lakes. **`src/map/` is inside every component check**: the ESLint class and hue bans take `src/map/**` beside `components/*.tsx`, and so do the per-file checks in `tools/eslint/checks/styles.js` and the source glob `styles.test.ts` keeps for its measured rules, because a folder of its own must not be a way out of the rules the component was under. The ESLint self-test lints one hue at a path under `map/` with the real config to prove the glob reaches it
- `src/map/controller.ts` — the latest props for the handlers `MapView` registers once, on `load` (#410): draw mode, the displayed rows and the Windy inputs a result popup needs, the fire warnings, the POI list and its two callbacks, the sheet's bottom padding for the framing calls inside the mount effect, and `onCameraMove`, where `map/camera.ts` sends the settled camera. A MapLibre handler closes over the first render's props for the session, and the component used to answer that with six mirror refs and four effects that did nothing but copy props into them. Now `MapView` holds one controller in `useState`, writes it in ONE effect declared before every other effect, and each handler reads `controller.inputs` when its event fires; a value copied out at registration is the stale closure the object exists to prevent, and the `map-shared-rules` check fails a destructure of it anywhere in the map's wiring. `resultAt` and `fireWarningAt` are the two reads the result popup makes. Separate because it is plain data with no map in it, so `controller.test.ts` can show in node that a handler made before an update sees the update
- `src/map/drawRing.ts` — the drawn ring on the map (#410): the `draw` source, the fill and outline, the midpoint and vertex handles (hidden outside draw mode, which is what stops a handle firing at all), the vertex drag by mouse or one finger, the midpoint insert that starts a drag on the new vertex, the remove-point popup, and `commitRing`, the one way an edit reaches React: on a click, a drag's end, an insert or a removal, never mid-drag, so the URL is not rewritten on every pointer move. It does not own the points: the component hands it the holder, and it edits that through the pure `ringPolygon`, `moveVertex`, `removeVertex` and `insertOnSegment` in `utils/drawGeometry.ts`. `DRAW_COLOR` lives here and stays a raw hex until #365 decides the map's paint
- `src/map/camera.ts` — the camera reported to the share link (#292): one `moveend` listener handing the settled centre and zoom to `controller.inputs.onCameraMove` with `isReaderMove`'s answer, and one report when it mounts, because the opening frame runs before the features mount and its own `moveend` has no listener. The callback writes the link without React state, so a pan renders nothing. Mounted last by `mountFeatures`; it adds no layer
- `src/map/features.ts` — every feature on the map, mounted in the order its layers stack (#410): the basemap patch under the style's labels, then the forecast grid, smoke, fire, the drawn ring, the markers and the pending dots, then the POI popups and the general click, which add no layers and go last because a handler registered later answers later. It also owns the rest cursor (a crosshair in draw mode, the default hand outside it) that every module hands back to. `mountFeatures` returns the handles the component's effects drive. Separate so that the whole stack mounts on `testSupport/stubMap.ts`, where `features.test.ts` pins it layer by layer: the order was a comment and a text check while it lived in the load handler
- `src/map/click.ts` — the one click on the map that is not on a layer of its own (#410): every clickable layer asked in one query, and `utils/mapClick.ts`'s rule deciding from the whole answer whether to open a fire's page, place a point, open a plume's popup, or clear the board. The layers that open popups of their own keep their handlers in their modules
- `src/map/controls.ts` — the map's controls (#410): the zoom and compass buttons, geolocate and the scale with box zoom turned off so shift can pin popups, and `addAttribution`, the attribution at the sheet's breakpoint, folded on add. The component re-adds the attribution when the width crosses the breakpoint, because `compact` is read once
- `src/map/popups.ts` — the popups' shared rules (#410): `isPinning` (shift keeps the popups already open), `popupOptions` (the width a popup takes from the canvas), and `createPopupBoard`, the one board every popup on the map goes on. `closeOnClick` is fixed when a popup is made, so it cannot tell a popup to survive the shift-click that pins a second one; the board is how a click without shift clears every popup, pinned ones included. `MapView` holds one board in `useState` and hands it to the smoke overlay, the results layer and the POI popups. Separate because it is plain data with MapLibre imported for its types only, so `popups.test.ts` runs it in node
- `src/map/resultsLayer.ts` — the analysis on the map (#410): the `results` source with its circles, wind arrows, rank digits and labels, the `pending-destinations` dots above them, the marker click that opens the forecast popup for the matched row, the cursor over a marker, and `openPopup`, the same popup for a click on a row's rank in the table. `update` is the marker path a playback tick runs (`updateResults` sets the source, and the arrows' visibility is set only when `windArrowsShowing` in `utils/resultFeatures.ts` changes its answer), so it must stay one `setData` a tick. The wind arrow image lives here, named for the markers, and the forecast grid registers it first. `RESULT_MARKER_LAYER` is the id the general click and the POI popups ask about. A table row's popup goes on the popup board like every other one, so a second table click replaces it rather than stacking
- `src/map/poiPopup.ts` — the clickable basemap peaks and lakes (#410): the click popup whose button adds the place as a destination or takes it back out, the cursor over one (never in draw mode), and `setPointed`, the glow that lights them while the panel points at them. The layers are the basemap's (`enhanceBasemap` adds them), so it adds none and only listens. A marker or a fire perimeter under the click takes it instead, and in draw mode the labels are scenery. Separate from `utils/poiPopup.ts`, which is the popup's markup and is pure
- `src/map/overlays/forecastGrid.ts` — the forecast grid's drawing (#410): the image source and raster layer the field is painted into, the per-cell wind arrows on a point source of their own (it registers the wind arrow image from `map/resultsLayer.ts`, being the first layer to name it, and shows the arrows on the markers' own `windArrowsShowing` rule), and `rasterImage`, the canvas that turns a `utils/forecastGrid.ts` raster into pixels. `mountForecastGrid` adds them on `load`, lowest of every overlay; `update` repaints the field and the arrows from one set of props, and `gridRedraws` is the pure rule for which half a change reaches (a style switch or a re-rank leaves the arrows' source alone), so a render that moves neither costs nothing. Separate from `utils/forecastGrid.ts` because that module is the pure half and this one needs a map and a canvas
- `src/map/overlays/smoke.ts` — the NOAA smoke overlay (#410): the source, a fill per density with the lightest lowest, the outline over them, the pointer over a plume (never in draw mode), the click popup, and the once-per-toggle fetch whose late answer is dropped if the toggle was undone. Which plume a click means is still `utils/mapClick.ts`'s call; the component asks this module to open the popup for it. Owns no pinning of its own: it takes the map's one popup board (`map/popups.ts`), because every popup on the map shares it
- `src/map/overlays/wildfires.ts` — the NIFC wildfire overlay (#410): the fill and outline, the hover popup with its grace close (`FIRE_POPUP_GRACE_MS`) and its same-fire anchoring, and the viewport fetch that runs while the overlay is on, re-asked on a settled pan. `fireDetailFor` is the pure choice between the server's coarse and full copies, and `fireLinkAt` the NIFC link both the hover popup and a click on a perimeter open. The popup's timer and the fetch's abort are torn down in the one `update` that turns the overlay off, which is why they are here rather than in three refs of the component
- `src/map/overlays/radar.ts` — the IEM radar loop (#410): its frames, created on toggle beneath the first smoke fill and removed on untoggle so nobody who never asked downloads a tile; the warm-up that arms them one per `RADAR_WARM_MS` until every source reports loaded; and which frame is on screen, an opacity flip rather than a fetch. `activeOffset` clamps a playhead to the loop
- `src/map/overlays/snow.ts` — the NOHRSC snow depth field (#410): one raster source and layer created on toggle and removed on untoggle, for the radar's reason. `snowBeneath` is the pure insertion rule: under the loop where the loop is up and under the smoke fills otherwise, so snow lands under rain whichever is switched on first. The component hands it its prop BEFORE the radar's, so a link carrying both puts the field in first
