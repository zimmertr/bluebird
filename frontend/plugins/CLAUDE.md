# Frontend layout: `plugins/`

The build's own Vite plugins. They run in node at build time and never reach the browser, so they sit outside `src/`: `tsconfig.json` covers `src/` alone and ships no node types, the way `vite.config.ts` beside this directory is not typechecked either. Their tests run in Vitest's node project (`vitest.config.ts` includes `plugins/**/*.test.ts`). `src/index.css` keeps Tailwind from scanning this directory, because `licenses/` holds upstream prose nobody reviews for class names.

- `plugins/thirdPartyLicenses.ts` — writes the npm half of the image's `third-party-licenses.txt` (#571), which the pod serves at `/third-party-licenses.txt`. It lists what the build actually ships rather than what package.json names: the chunks' `moduleIds` (the module graph), the same for Vite's worker builds through a second plugin sharing one record (the MapLibre worker is a separate bundle the main build's hook never sees), the bare `@import`s in the app's own stylesheets (Tailwind inlines `tailwindcss` and MapLibre's CSS, so they never enter the graph), and `VENDORED_FILES`, the Swagger UI files the Dockerfile copies out of node_modules. Each package contributes every LICENSE, LICENCE, COPYING or NOTICE file it ships, plus a vendored bundle's own `<file>.LICENSE.txt`; a package with none falls back to `licenses/<name>.txt`, and with neither the build fails. Vite 8's built-in `build.license` does the first of those four and silently writes a package with no text, which is why this exists. The test holds `VENDORED_FILES` to the Dockerfile's COPY lines and fails when a package in `licenses/` starts shipping its own text. Record: [0086](../../docs/decisions/0086-license-notices-built-into-the-image.md)
- `plugins/licenses/` — license texts copied from a package's own repository for a package whose npm tarball carries none, one `<name>.txt` per package (`@scope/name` as `@scope__name.txt`). Today only `victory-vendor`, which recharts imports and whose MIT text lives at the Victory monorepo's root.
