# 0045. Temperature is reported at the destination's elevation, with no floor

Verbatim guide text at 971fede, copied before the edit to the template.

## From `CLAUDE.md`, line 138

The elevation-adjusted TEMPERATURE is the same pair one metric over (#443), and is deliberately unnumbered here because the count above already has two sevenths: `_TEMP_LEVELS`/`_temp_at_elevation` in `aggregation.py` ↔ `TEMP_LEVELS`/`tempAtElevation` in `openMeteoAggregate.ts` — the same five levels at the same ISA heights, interpolated the same way, with every gap (no elevation, below ~762 m, a null level, an archive window) degrading to `temperature_2m`. It is part of the vector-pinned aggregation and rides the same elevation cache key. **It has NO floor, and that is the one way it differs from the wind**: `max` there is a physical statement (altitude can only add exposure), where a summit is genuinely colder than the free air on a calm clear night and warmer than it under an inversion, so a clamp either way would report a number no model produced. **The grid does NOT keep `temperature_2m`**, and the wrong instinct is to assume it does: `terrainElevation` computes ONE `elevationFt` and hands it to both `weatherMetrics` and `weatherSeries`, so a temperature adjustment added to those readers reaches the lattice automatically — measured 2026-09-16 at the lattice point under Dome Peak, which paints 38.7 °F where its `temperature_2m` minimum is 23.9 °F. The grid is therefore the free air at the TERRAIN's height and the marker is the free air at the DESTINATION's, which is the same rule the wind follows and the same reason the two can differ over a summit.
