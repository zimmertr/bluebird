## From `frontend/src/CLAUDE.md`, line 87

- `src/utils/snowDepth.ts` — the NOHRSC snow depth overlay's pure half (#446): the tile-URL builder, the source and layer ids, the coverage extent, NOAA's twelve-band legend table and the strip the legend draws from it (through `legendRamp.ts`, the same builder the metric key uses). The service has no cached tiles (`singleFusedMapCache` is false and it advertises no Tilemap), so the layer is an ArcGIS `export` call driven as a raster source through MapLibre's `{bbox-epsg-3857}` token, and `imageSR=3857` is not optional — the service's own reference is EPSG:4269 and an image in it does not sit on a Web Mercator map. Three things bound what the layer costs, because the service refuses caching outright (`max-age=0, must-revalidate`) and renders every image on request: a 512 px tile, since a render costs ~0.46 s whatever its size; the extent as the source's `bounds`, so nothing is asked for outside the analysis; and `SNOW_MAX_ZOOM`, past which the 1 km grid has no more detail and MapLibre magnifies what it holds. The colours are NOAA's, decoded from the legend endpoint's swatches, for the reason the radar legend takes IEM's: the map draws NOAA's rendered image, so the key has to describe that image. The first band is transparent by NOAA's own paint, which is why the ramp has eleven blocks and not twelve. Measured 2026-09-16: 11 renders fill a 1440x597 map, 4 to 6 more per full-width pan, 200 to 255 ms each; a 402x874 phone pays 6 and 0 to 3
