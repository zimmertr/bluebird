# Backend layout

Every module under `backend/`: what it owns, and why it is separate. This file is
one half of the module layout that used to sit in the repo root's
[`CLAUDE.md`](../CLAUDE.md), and it is loaded only when a session touches this
tree. Everything that governs a change to these modules — the rules, the
Python/TypeScript mirrors table, the interaction model, the CI/CD flow — stays in
that root file. Read it first; this is a directory, not a manual.

**A new source module gets a bullet here, in the same PR that adds it.** The bullet says what the module OWNS and why it is separate, at the density of the ones around it; one line is a fine answer for a twenty-line module. Nothing enforces this. A session reads this list before it writes code, so a module named nowhere here is one the next session rediscovers and re-decides (#392).

- `app/main.py` — FastAPI app + OpenAPI metadata (tags, description), logging setup (includes custom `TRACE` level at value 5), self-hosted Swagger UI at `/docs`, static file mount. `docs_url`/`redoc_url` are `None` in the **constructor**: `FastAPI.setup()` registers those routes at the end of `__init__`, so assigning them afterward has no effect
- `app/version.py` — build identity read from `APP_VERSION`/`APP_COMMIT`/`APP_BUILT_AT`, baked by the Dockerfile; `"dev"` everywhere else
- `app/env.py` — `env_int`, the one reader for every numeric env knob (absent or unparseable takes the documented default, and logs). It imports nothing from `app`, which is what lets `telemetry.py` use it: `ratelimit/` imports telemetry, so telemetry can import nothing of ratelimit, and that edge is why four modules each carried their own copy (#388)
- `app/limits.py` — the limit constants and the archive boundary: the polygon and candidate caps, the archive's reach, the horizon slack pair, `PAST_DATA_DAYS`, `ARCHIVE_STRADDLE_DAYS`, the `limit` bounds, and `archive_boundary`/`window_source`, the one place a window is classified. Its own module because the services, `/api/capabilities` and `generate_mirrored_constants.py` read these numbers without needing a single Pydantic model, and each one sits beside the dated measurement behind it
- `app/forecast_models.py` — `ForecastModel`, `ModelInfo`, `MODEL_INFO` and `DEFAULT_FORECAST_MODEL`. Its own module because the table is editorial data rather than a wire shape: the weather service and `/api/capabilities` read it without any request model, and its declaration order is the published order, so it must never be sorted
- `app/models/` — the Pydantic request and response models, one module per endpoint family (#406). `__init__.py` re-exports every name the old single file held, the two modules above included, so `from app.models import X` works wherever it was written; a test that patches a name patches the module that defines it, because a patch on the re-export never reaches the code that reads it. `common.py` holds what both requests share: `DestinationType`, `ForecastMode`, `SortBy`, the snow-depth descriptions, `GeoPolygon`, `bbox_area_km2`, `CustomDestination`, `_check_polygon_area`, and `_DiscoveryFields`. `AnalyzeRequest` and `DestinationsRequest` both open with `_DiscoveryFields`, the seven fields and three validators that decide which destinations a request is about (#388), so the polygon ceiling, the custom-list ceiling and the `custom` rejection cannot answer the same request two ways. Descriptions stay per class: they are approved copy and the two endpoints genuinely read differently, so the four that differ are restated on `DestinationsRequest` and the two words the validator messages differ by ride on `_list_verb`/`_split_noun`. `_check_polygon_area` reads `bbox_area_km2` inside `common.py`, so the polygon-cap tests patch `models.common`. `analyze.py` is `AnalyzeRequest` with its forecast-mode and window validators, the result and response shapes, and `ApiErrorInfo`/`ErrorResponse`, which every route documents. `destinations.py` is the discovery request and response. The committed snapshot is written `sort_keys=True`, so field order never reaches `openapi.json`
- `app/error_codes.py` — the closed `ErrorCode` vocabulary, its `retryable` table, and the `ApiError`/`api_error_handler` pair that render it (#153). Every hand-raised JSON error answers `{detail, error: {code, retryable}}`: `detail` stays the approved sentence and may be reworded, the code is contract and is published in `openapi.json` as an enum. A raise site names a code and nothing else builds the shape, except the two answers that never raise (the over-cap refusal, and `notfound.py`'s 404/405), which call `error_object`. The handler is registered for `ApiError` **alone** — Starlette resolves by MRO, so a plain `HTTPException` keeps FastAPI's stock body, which is what leaves `main.py`'s document-page 404 outside the API contract. `test_error_codes.py` fails any `HTTPException(` under `routes/` or in `ratelimit/`, because the omission is otherwise invisible: the route still works and only a client branching on the code ever notices. The SSE stream carries the same member on its terminal `error` event (`_sse_error`), since a stream already open has no status code left to fail with. Pydantic's 422 is deliberately untouched — its `detail` is a list of field objects and is already machine-readable — while the hand-parsed `bbox` 422s in `wildfires.py` do carry `validation`
- `app/ratelimit/` — per-client token buckets and pod-wide upstream budgets, one module each (#406), because one bounds a single client address and the other the whole pod's spend. `client.py` is `client_key`, `RateLimiter`, the five limiter instances and their route dependencies (429 + Retry-After on analyze, destinations, geocode, wildfires and smoke). `upstream.py` is `BudgetExhausted`, `UpstreamBudget`, `MinIntervalGate` and the `WeightedBudget` pacers with their instances (queue then shed 503; best-effort AQI degrades to null instead). `__init__.py` re-exports both **except the five limiters**: the route dependencies and `/api/capabilities` read them as `ratelimit.client.X`, so a test patches them there, and leaving them out of the package makes a patch on the wrong module fail rather than pass silently. The budgets are the other way round: the services read them through the package, so tests patch them on `ratelimit`. In-memory per pod by design (~replicas × the configured ceiling); env knobs documented in the `docs/CONFIGURATION.md` table and published by `/api/capabilities` under `limits.rate`. Traffic/limits changes update [`docs/TRAFFIC.md`](docs/TRAFFIC.md) and [`docs/LIMITS.md`](docs/LIMITS.md) in the same PR
- `app/telemetry.py` — every Prometheus metric family in one module (#77), served on its own port (`METRICS_PORT`, default 9464) from the lifespan, **never as a route on the app**: the #240 gateway allowlist filters `/api/*` only, so a `/metrics` route on 8000 would be public — and the second port keeps `openapi.json` unchanged. Counters wire into what the code already counts (the `ratelimit/upstream.py` pacers at their existing log points, `TTLCache.hits`/`misses` via a collector) rather than keeping parallel books. Label values are bounded by construction — route TEMPLATES (never raw paths; the static mount collapses to `static`), mirror hosts, closed outcome sets, budget provider strings verbatim — and never coordinates, a client address or an API key. Two labels name a side rather than a supplier (#317): `client` on the HTTP families is `web` or `api`, read off `Sec-Fetch-Site: same-origin` because a browser stamps it on the app's own fetches and page script cannot forge it, and `quota` on the three Open-Meteo families is `pod` or `caller`, saying whose quota a batch spent. Both are a PICTURE, never a boundary: `curl` can send that header, so nothing may gate on `client`. `test_telemetry.py` fails any `bluebird_forecast_*` sample that grows a label outside its allowlist. Metrics changes update the Grafana dashboard in `Kubernetes-Manifests` (`observability/kube-prometheus-stack/`) in a sibling PR
- `app/security_headers.py` — the security response headers every response carries (#132), added as the **outermost** middleware so a route, a static file and a 404 are all covered, and pure ASGI rather than `BaseHTTPMiddleware` because the analyze route streams and the base class would buffer it. App-owned rather than mesh-owned for one reason: the `connect-src` allowlist IS the list of hosts the browser bundle fetches (Open-Meteo's three services, `tiles.openfreemap.org`, `mesonet.agron.iastate.edu`, `mapservices.weather.noaa.gov`; Overpass, Nominatim, NIFC and NOAA's HMS smoke files are absent because the pod fetches those, while NOAA's snow map service renders per tile and the browser asks it directly — #446), so it changes when a frontend overlay changes and belongs beside the code that defines it. `test_security_headers.py` reads `frontend/src` as text and fails on any host there that is neither in `connect-src` nor in its link-only list, in both directions. Three values are measurements, not habits: `data:` in `connect-src` (MapLibre loads an image source by *fetching* its URL, and the forecast grid's raster is a canvas `data:` URL), `blob:` in `worker-src` (MapLibre builds its worker from a Blob), and `'unsafe-inline'` in `style-src` (map popups are HTML strings with inline style attributes handed to `setHTML`; `style-src-attr` would carry it alone but falls back to `style-src` on the engines a CSP protects most). `script-src` stays strict, because the built pages carry no inline script. `/docs` is the one path with its own policy, narrower everywhere except Swagger UI's inline init script, which is allowed by a hash **taken from the rendered page** rather than pinned. Header changes update [`docs/TRAFFIC.md`](docs/TRAFFIC.md) in the same PR
- `app/routes/version.py`, `app/routes/capabilities.py` — build identity and the machine-readable limits/feature contract
- `app/routes/analyze.py` — the two analyze routes (JSON and SSE), `API_KEY_HEADER`, the over-cap refusal, and `_sse_error`; the align/assemble/rank/filter helpers the browser ports live here too. **The analysis itself is `_run_analysis`, once, and the two routes are presenters over it** (#384): it yields `Status`/`Progress`/`Failure`/`Refusal`/`Result`, the SSE route renders each through `_render_sse`, and the JSON route drops the mid-flight ones and answers the terminal one. A `Failure` carries a whole `ApiError`, so one raise site decides the status, the sentence, the code and `Retry-After` for both arms. Both routes are public API since #317, so neither can be dropped and a rule added to one arm alone is a bug — which is what the two hand-kept copies kept producing. Discovery's four-branch failure mapping is `discover()` in the same module, shared with `routes/destinations.py`, and is the only place `"OpenStreetMap is not available. Try again later."` is written
- `app/routes/geocode.py` — `GET /api/geocode`, a thin Nominatim proxy paced by `NOMINATIM_GATE`; exists because the policy wants a real User-Agent a browser cannot set, and forbids autocomplete
- `app/routes/config.py` — `GET /api/config`, the preview banner's `PREVIEW_BANNER`/`PREVIEW_PR`/`PREVIEW_COMMIT`
- `app/cache_headers.py` — the `Cache-Control` header by path class (#354), registered beside the security headers; the two read different headers so their order carries nothing
- `app/services/errors.py` — the upstream exception vocabulary (`UpstreamError`, `UpstreamRateLimited`, `ModelCoverageError`, `InvalidApiKeyError`), `classify_http_error`, and the 429 parser
- `app/services/wfigs_coverage.py` — the coarse, outward-biased outline of where WFIGS can see, published as a foreign member on `/api/wildfires` so an unchecked row reads `N/A` rather than clear
- `app/routes/smoke.py` — `GET /api/smoke`: NOAA HMS smoke plumes for the whole of North America, with no bbox parameter, because a busy day measured under half a megabyte and a filter would be ceremony where NIFC's 16.5 MB genuinely needed one. `analysis_date` rides as a foreign member beside `fetched_at`: HMS publishes one dated file per day and the first analyst pass lands around late morning Eastern, so before then the fetch falls back to yesterday and that field is the only thing that says so
- `app/routes/wildfires.py` — `GET /api/wildfires`: the snapshot filtered to a bbox, at the fidelity the caller names, with `fetched_at` as a GeoJSON foreign member rather than a response header, so it survives being saved to a file (the SPA ignores it; it exists for API callers, who have no other way to know how current an answer is). Returns a raw `Response` so the stored feature text passes through unre-encoded; `response_model` still documents the shape. Its own rate bucket, the loosest of the five, tied with smoke, because a pan costs no upstream call
- `app/routes/destinations.py` — `POST /api/destinations`: discovery without forecasts, **and** resolution of `custom_destinations` against OSM (the SPA's only per-analysis server call, now on the custom-only path too; shares the analyze rate-limit bucket). At least one of `polygon` or `custom_destinations` is required; a union comes back merged, custom rows winning by name or 5-decimal coordinate
- `app/routes/notfound.py` — `/api` catch-all returning a JSON 404 (or a 405 with `Allow`) instead of letting unknown API paths fall into the SPA static mount. Must stay the **last** router registered under `/api`
- `scripts/generate_openapi.py` — writes/verifies the committed `backend/openapi.json`
- `scripts/generate_weather_vectors.py` — regenerates `tests/data/weather_vectors.json` from the reference aggregation (see the vectors rule above)
- `app/services/osm/` — everything this app asks Overpass, in three modules (#406); `__init__.py` re-exports them, and the routes call `osm.query_osm` and `osm.enrich_custom` through it. `query.py` is the query text and the reading of an element: `IMPLEMENTED_TYPES` gates which destination types are discoverable, `_CLAUSES` holds each type's QL as a *fragment* so several types union into one request, and `_ele_ft` is the one reading of an `ele` tag both other modules use. `mirrors.py` is the network: the 3-endpoint `OVERPASS_MIRRORS` table with its per-mirror budgets and timeouts, `query_osm`, and `_post_with_fallback`, the failover every Overpass request goes through. `enrich.py` is `enrich_custom`, the other direction: one batched `around` query resolves caller-supplied coordinates to the nearest peak within `CUSTOM_MATCH_RADIUS_M` (150 m, measured — see the comment before changing it), filling elevation and `osm_id` only where the caller supplied none. Best-effort by construction: every failure path returns the rows unchanged, so an analysis never fails over an elevation. It calls `mirrors._post_with_fallback` through the module, so a test patches `osm.mirrors` once and reaches both discovery and enrichment
- `app/services/openmeteo_fetch.py` — the pipeline both Open-Meteo services run (#387): the cache-miss scan, the chunking at `BATCH_SIZE` and `MAX_CONCURRENT_BATCHES` (which live here, once), the weighted pacer and the in-flight slot, the timed request with its telemetry and classification, and the write-back. What the two services do **not** share is what a failed batch does, so `on_error` is a **required keyword argument with no default** — weather raises and fails the analysis, air quality degrades to null rows and the first 429 stops the batches behind it. A default either way fails silently, and `tests/test_openmeteo_fetch.py` fails if one is added or if a service re-declares a batch constant. `request_openmeteo` takes the shared client rather than reaching for it, and `redacted_params`/`redacted_error`/`quota_label` live here because every request through it logs and labels the same way
- `app/services/aggregation.py` — the vector-pinned arithmetic and nothing else (#405): the weather and air-quality aggregates and series, the elevation adjustments, the freezing level's unit, the stamp helpers, the variable list, and `_join_hours`, the join that makes a window split across two endpoints look like any other window. Its own module so a reviewer can read it beside its browser port, `frontend/src/utils/openMeteoAggregate.ts`: the two list the same functions in the same order, and `openMeteoAggregate.test.ts` fails when they drift. `PROVIDER` lives here because the one refusal this module raises names it and `weather.py` imports from here
- `app/services/weather.py` — the weather half: the endpoint split, the request, and two things the shared pipeline cannot decide for it — the one automatic resume of a minutely 429, and the 400 that means the chosen model does not cover the batch (`_coverage_guard`, handed in as the request's status-error hook, because only this service knows which model it asked for)
- `app/services/air_quality.py` — the air-quality half: the CAMS horizon clamp, the request, and `on_error="degrade"`. It reads `hour_param` from `weather.py`, which is where the window convention lives, and its aggregation from `aggregation.py`
- `app/services/openmeteo_weight.py` — the weighted-call accounting every capacity number uses
- `app/services/http.py` — the one `httpx.AsyncClient` the Open-Meteo services share (forecast, archive, air quality, and their customer twins), closed by `main.py`'s lifespan, **and** the one `USER_AGENT`/`HEADERS` every fetching module sends (`osm/mirrors.py`, `nifc.py`, `hms.py`, and `routes/geocode.py`, which had drifted to a second spelling of the same product; #388). The shared client itself sends no User-Agent, which is Open-Meteo's existing behaviour and not a thing to change quietly. httpx pools connections per *client*, so a client built inside the chunk loop discarded the pool and paid a fresh TCP+TLS handshake every batch: measured 2026-07-31 at ~540 ms per batch (720 ms per request cold, 178 ms warm). Batch size is **not** the lever here and was measured and left at 50 (issue #182): weight is per-location, so bigger batches buy no throughput under the pacer, and Open-Meteo's nginx caps the request URI at 8,192 bytes, which 250 locations of 7-decimal coordinates already fills to 7,485
- `app/services/cache.py` — TTL/LRU caches: discovery (~10 min per polygon+type), custom-coordinate resolution (~10 min per point *set*, order-independent), and per-location forecasts (~15 min). **Not** the wildfire snapshot: `TTLCache.get()` deletes an expired entry, and that entry is exactly what `nifc.py` must keep hold of
- `app/services/snapshot.py` — `SnapshotCache`, the singleflight, **stale-tolerant** holder both national overlays use: an aged snapshot is served immediately and refreshed *behind* the request, and the only state that means "we cannot answer" is having never fetched at all. Deliberately not a `TTLCache`: that one deletes an entry the moment it expires, which is exactly the value these two must hold on to. It owns everything else the two overlays share (#388): `cache_factory`, which wires the cache to one upstream's fetch and knobs and returns the module-level factory (`perimeter_cache`, `smoke_cache`) whose keywords a test overrides; `unavailable_message`; and `snapshot_or_503`, the one cold-cache answer both routes call, so the status, the sentence and the `Retry-After` cannot differ between them. It raises `ApiError` from the services layer, as `ratelimit/client.py` already does, rather than leaving two copies of the raise in the routes
- `app/services/hms.py` — the NOAA HMS smoke snapshot behind `GET /api/smoke` (issue #121). One dated KML per day off NOAA's own file server, not an ArcGIS mirror of the same data — the shared-org-quota failure mode #203 removed from the fire overlay. The date is **Eastern**, because that is the shift the analysts work, and a UTC date would ask for tomorrow's file for five hours every evening; a 404 falls back one day, which is the normal morning state rather than an outage. Density lives in the placemark's `styleUrl` rather than in the data, in a vocabulary NOAA has changed once already (numeric to named, 2022-07-19), so an unrecognized style renders as Light with the raw value kept rather than being dropped. `ospo.noaa.gov/data/land/fire/smoke.kml` is advertised as current and is frozen at 2022-07-18: do not use it
- `app/services/nifc.py` — the national wildfire-perimeter snapshot behind `GET /api/wildfires` (issue #203). One paged ArcGIS query per fidelity (full-resolution for API callers, ~56 m simplified for the map picture and the proximity math — see the fireProximity bullet) covering the whole country with no geometry filter, which is both the smallest query to describe and the one that sidesteps the Aleutians straddling the antimeridian. Measured 2026-07-31 at 232 active fires: 16.5 MB full, 1.3 MB coarse, so the country fits in a pod and nothing keys on the caller's bbox. Features are held as the JSON text NIFC sent plus a per-feature bbox, because parsing 861k coordinates costs ~100 MB in Python and a viewport would then be a re-encode; a request is a filter and a join. `perimeter_cache()` returns a `SnapshotCache`, singleflight (`asyncio.Lock`) and **stale-tolerant**: an aged snapshot is served immediately and refreshed *behind* the request, since a cold fetch measured 6.7 s and no visitor should pay that to learn what the last one already knew. ArcGIS refuses an exhausted quota with **HTTP 200** and the error in the body, so `raise_for_status` learns nothing
- `app/services/snodas.py` — today's snow depth for any coordinate, from one national grid the pod holds (#449). NSIDC publishes each day's SNODAS products as one tar; this pulls the **unmasked** snow depth member out of it by its `1036` product code (24.1N to 58.23N, 130.5W to 62.25W: the contiguous United States, southern Canada and northern Mexico, which is the same box the map's snow layer draws), reads the geometry out of the `.txt.gz` header beside it rather than assuming one (NSIDC has moved the masked extent once), and keeps the 8192x4096 array of big-endian int16 millimetres as `bytes` — 64 MiB, never written to disk, because the pod runs `readOnlyRootFilesystem`. A lookup is one `struct.unpack_from` at a computed offset (~3.5 us), so a 1,500-destination analysis costs no upstream call at all. A `SnapshotCache` through `cache_factory` like the two overlays, with two differences that are the whole of its design. The fetch checks the HELD snapshot's date first and answers with it unchanged for most of the day, so an hourly refresh is one `HEAD`; the day's tar is published around 13:15 UTC and a 404 falls back one day, the `hms.py` pattern. And `fill_snow_depth` reads the cache through `current_or_schedule` rather than `get`, so **no request ever waits for a cold grid**: it answers nulls, schedules the refresh behind itself, and the rows read `N/A` — which is the same answer a destination outside the grid gets, and is why a report with no depths also carries no `snow_analysis_date` to caption itself with. `warm_up()` is what the lifespan schedules so that is rare, and `conftest.py` neutralizes both it and the cache autouse so no test reaches NSIDC
