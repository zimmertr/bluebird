# Backend layout

Every module under `backend/`: what it owns, and why it is separate. This file is
one half of the module layout that used to sit in the repo root's
[`CLAUDE.md`](../CLAUDE.md), and it is loaded only when a session touches this
tree. Everything that governs a change to these modules — the rules, the
Python/TypeScript mirrors table, the interaction model, the CI/CD flow — stays in
that root file. Read it first; this is a directory, not a manual.

**A new source module gets a bullet here, in the same PR that adds it.** The bullet says what the module OWNS and why it is separate, at the density of the ones around it; one line is a fine answer for a twenty-line module. Nothing enforces this. A session reads this list before it writes code, so a module named nowhere here is one the next session rediscovers and re-decides (#392).

- `app/main.py` — FastAPI app + OpenAPI metadata (tags, description), logging setup (includes custom `TRACE` level at value 5), self-hosted Swagger UI at `/docs`, static file mount. `docs_url`/`redoc_url` are `None` in the **constructor**: `FastAPI.setup()` registers those routes at the end of `__init__`, so assigning them afterward has no effect
- `app/version.py` — build identity read from `APP_VERSION`/`APP_COMMIT`/`APP_BUILT_AT`, baked by the Dockerfile; `"dev"` everywhere else
- `app/env.py` — `env_int`, the one reader for every numeric env knob (absent or unparseable takes the documented default, and logs). It imports nothing from `app`, which is what lets `telemetry.py` use it: `ratelimit/` imports telemetry, so telemetry can import nothing of ratelimit, and that edge is why four modules each carried their own copy (#388)
- `app/limits.py` — the limit constants and the archive boundary: the polygon and candidate caps, the archive's reach, the horizon slack pair, `PAST_DATA_DAYS`, `ARCHIVE_STRADDLE_DAYS`, the `limit` bounds, and `archive_boundary`/`window_source`, the one place a window is classified. Its own module because the services, `/api/capabilities` and `generate_mirrored_constants.py` read these numbers without needing a single Pydantic model, and each one sits beside the dated measurement behind it
- `app/forecast_models.py` — `ForecastModel`, `ModelInfo`, `MODEL_INFO` and `DEFAULT_FORECAST_MODEL`. Its own module because the table is editorial data rather than a wire shape: the weather service and `/api/capabilities` read it without any request model, and its declaration order is the published order, so it must never be sorted
- `app/models/` — the Pydantic request and response models, one module per endpoint family (#406). `__init__.py` re-exports every name the old single file held, the two modules above included, so `from app.models import X` works wherever it was written; a test that patches a name patches the module that defines it, because a patch on the re-export never reaches the code that reads it. `common.py` holds what both requests share: `DestinationType`, `ForecastMode`, `SortBy`, the snow-depth descriptions, `GeoPolygon`, `bbox_area_km2`, `CustomDestination`, `_check_polygon_area`, and `_DiscoveryFields`, plus the two configs the 1.0 contract rests on (#563): `_REQUEST_CONFIG` refuses an unknown field on every request shape (a polygon's `bbox` is declared and never read) and `_RESPONSE_CONFIG` marks every response field required. `no_range_inverted` on `_DiscoveryFields` refuses a `min_X` above its `max_X`, with the pairs read off the model's own fields so a new pair needs no table. A range lives on its `Field` so the schema publishes it, and `_bound_broken` lets a wrap validator answer a broken bound with its approved sentence instead of Pydantic's. `AnalyzeRequest` and `DestinationsRequest` both open with `_DiscoveryFields`, the seven fields and three validators that decide which destinations a request is about (#388), so the polygon ceiling, the custom-list ceiling and the `custom` rejection cannot answer the same request two ways. Descriptions stay per class: they are approved copy and the two endpoints genuinely read differently, so the four that differ are restated on `DestinationsRequest` and the two words the validator messages differ by ride on `_list_verb`/`_split_noun`. `GeoPolygon` types its rings rather than validating them (at least four positions, each a longitude and a latitude in range), so a malformed ring is Pydantic's own `422` at the position that is wrong instead of an `IndexError` in `bbox_area_km2` (#564). An optional third number, an altitude, is accepted and dropped in `_position_schema`, the way `bbox` is, so every reader sees only `(lon, lat)`. `_check_polygon_area` reads `bbox_area_km2` inside `common.py`, so the polygon-cap tests patch `models.common`. `analyze.py` is `AnalyzeRequest` with its forecast-mode and window validators, the result and response shapes, and `ApiErrorInfo`/`ErrorResponse`, which every route documents. `window_within_servable_range` converts both ends to aware UTC before anything else reads them, so an offset names the instant ISO 8601 says, a naive stamp is read as UTC, and the horizon checks, `window_source`, `hour_param`, `_naive`, the AQI clamp and the cache keys all read one instant (#564). Record: [0078](../docs/decisions/0078-timestamp-offsets-honored.md) `destinations.py` is the discovery request and response. The committed snapshot is written `sort_keys=True`, so field order never reaches `openapi.json`
- `app/error_codes.py` — the closed `ErrorCode` vocabulary, its `retryable` table, and the `ApiError`/`api_error_handler` pair that render it (#153). Every hand-raised JSON error answers `{detail, error: {code, retryable}}`: `detail` stays the approved sentence and may be reworded, the code is contract and is published in `openapi.json` as an enum. A raise site names a code and nothing else builds the shape, except the two answers that never raise (the over-cap refusal, and `notfound.py`'s 404/405), which call `error_object`. The handler is registered for `ApiError` **alone** — Starlette resolves by MRO, so a plain `HTTPException` keeps FastAPI's stock body, which is what leaves `main.py`'s document-page 404 outside the API contract. ruff's `TID251` ban in `backend/ruff.toml` fails any `HTTPException` under `routes/` or in `ratelimit/`, because the omission is otherwise invisible: the route still works and only a client branching on the code ever notices. The SSE stream carries the same member on its terminal `error` event (`_sse_error`), since a stream already open has no status code left to fail with. Pydantic's 422 keeps its shape — its `detail` is a list of field objects and is already machine-readable, and it carries no `error` object — and `validation_error_handler` changes one thing in it: a `value_error` entry's `msg` loses Pydantic's `Value error, ` prefix, so the browser, which shows `msg` as-is, shows the sentence our own validator wrote. Meanwhile the hand-parsed `bbox` 422s in `services/bbox.py` do carry `validation`
- `app/ratelimit/` — per-client token buckets and pod-wide upstream budgets, one module each (#406), because one bounds a single client address and the other the whole pod's spend. `client.py` is `client_key`, `RateLimiter`, the six limiter instances and their route dependencies (429 + Retry-After on analyze, destinations, geocode, wildfires, smoke and closures). `upstream.py` is `BudgetExhausted`, `UpstreamBudget`, `MinIntervalGate` and the `WeightedBudget` pacers with their instances (queue then shed 503; best-effort AQI degrades to null instead). A `WeightedBudget` spends at most its budget in any 60 seconds, as a sliding-window log, because that is how Open-Meteo states its limit and a token bucket that starts full and refills at the same rate spends twice its budget in its first minute (#581); the browser's pacer in `openMeteo.ts` is its port. Record: [0075](../docs/decisions/0075-pacer-sliding-window.md) `__init__.py` re-exports both **except the six limiters**: the route dependencies and `/api/capabilities` read them as `ratelimit.client.X`, so a test patches them there, and leaving them out of the package makes a patch on the wrong module fail rather than pass silently. The budgets are the other way round: the services read them through the package, so tests patch them on `ratelimit`. In-memory per pod by design (~replicas × the configured ceiling); env knobs documented in the `docs/CONFIGURATION.md` table and published by `/api/capabilities` under `limits.rate`. Traffic/limits changes update [`docs/TRAFFIC.md`](../docs/TRAFFIC.md) and [`docs/LIMITS.md`](../docs/LIMITS.md) in the same PR
- `app/telemetry.py` — every Prometheus metric family in one module (#77), served on its own port (`METRICS_PORT`, default 9464) from the lifespan, **never as a route on the app**: the #240 gateway allowlist filters `/api/*` only, so a `/metrics` route on 8000 would be public — and the second port keeps `openapi.json` unchanged. Counters wire into what the code already counts (the `ratelimit/upstream.py` pacers at their existing log points, `TTLCache.hits`/`misses` via a collector) rather than keeping parallel books. Label values are bounded by construction — route TEMPLATES (never raw paths; the static mount collapses to `static`), mirror hosts, closed outcome sets, budget provider strings verbatim — and never coordinates, a client address or an API key. Two labels name a side rather than a supplier (#317): `client` on the HTTP families is `web` or `api`, read off `Sec-Fetch-Site: same-origin` because a browser stamps it on the app's own fetches and page script cannot forge it, and `quota` on the three Open-Meteo families is `pod` or `caller`, saying whose quota a batch spent. Both are a PICTURE, never a boundary: `curl` can send that header, so nothing may gate on `client`. `test_telemetry.py` fails any `bluebird_forecast_*` sample that grows a label outside its allowlist. `init_canary_series`, called from the lifespan, creates the 5xx children of `CANARY_ROUTES` at 0 (500 plus each route's declared 5xx from the OpenAPI document), because a child born at 1 reads 0 in `increase()` and the canary error-rate gate would miss its first 5xx (#574); never rename the family or its labels, since that gate passes on an empty result. Metrics changes update the Grafana dashboard in `Kubernetes-Manifests` (`observability/kube-prometheus-stack/`) in a sibling PR
- `app/security_headers.py` — the security response headers every response carries (#132), added as the **outermost** middleware so a route, a static file and a 404 are all covered, and pure ASGI rather than `BaseHTTPMiddleware` because the analyze route streams and the base class would buffer it. App-owned rather than mesh-owned for one reason: the `connect-src` allowlist IS the list of hosts the browser bundle fetches (Open-Meteo's three services, `tiles.openfreemap.org`, `mesonet.agron.iastate.edu`, `mapservices.weather.noaa.gov`; Overpass, Nominatim, NIFC, the Forest Service's closure layers and NOAA's HMS smoke files are absent because the pod fetches those, while NOAA's snow map service renders per tile and the browser asks it directly — #446), so it changes when a frontend overlay changes and belongs beside the code that defines it. `test_security_headers.py` reads `frontend/src` as text and fails on any host there that is neither in `connect-src` nor in its link-only list, in both directions. Three values are measurements, not habits: `data:` in `connect-src` (MapLibre loads an image source by *fetching* its URL, and the forecast grid's raster is a canvas `data:` URL), `blob:` in `worker-src` (MapLibre builds its worker from a Blob), and `'unsafe-inline'` in `style-src` (map popups are HTML strings with inline style attributes handed to `setHTML`; `style-src-attr` would carry it alone but falls back to `style-src` on the engines a CSP protects most). `script-src` stays strict, because the built pages carry no inline script. `/docs` is the one path with its own policy, narrower everywhere except Swagger UI's inline init script, which is allowed by a hash **taken from the rendered page** rather than pinned. The app sends no `Strict-Transport-Security`: the Cloudflare zone sends it, at `max-age=15552000` with no subdomains and no preload, and redirects plain HTTP to HTTPS, because a browser cannot be told to forget a `max-age` and one voice on that claim is easier to withdraw than two. Record: [0084](../docs/decisions/0084-hsts-at-the-edge-six-months.md) Header changes update [`docs/TRAFFIC.md`](../docs/TRAFFIC.md) in the same PR
- `app/routes/version.py`, `app/routes/capabilities.py` — build identity and the machine-readable limits/feature contract
- `app/routes/analyze/` — the two analyze routes and the analysis they present, one package (#540). `__init__.py` holds no code and re-exports only `router` (for `main.py`) and `API_KEY_HEADER` (for `/api/capabilities`); a test imports every other name from the module that defines it. `route.py` holds the two routes (JSON and SSE), `API_KEY_HEADER`, `_summarize_request` and `_run_analysis`, which only calls the phases in `phases.py` in order and stops at the first terminal event. **The analysis itself is `_run_analysis`, once, and the two routes are presenters over it** (#384): it yields the events, the SSE route renders each through `_render_sse`, and the JSON route drops the mid-flight ones and answers the terminal one. A `Failure` carries a whole `ApiError`, so one raise site decides the status, the sentence, the code and `Retry-After` for both arms. Both routes are public API since #317, so neither can be dropped and a rule added to one arm alone is a bug — which is what the two hand-kept copies kept producing. Its logger, and `phases.py`'s, is pinned to `app.routes.analyze`, the name `docs/CONFIGURATION.md` shows operators, rather than `__name__`. `phases.py` is the analysis, one function per phase, each with its own test in `tests/test_analyze_phases.py`: `_check_window` (the resolved `Window`, from one reading of the clock), `_find_candidates`, `_apply_cap` (the empty answer, the refusal, or the `Capped` set with today's snow depth), `_check_pacing` (an unkeyed analysis whose own batches the weather pacer would shed is refused before it spends, against `UPSTREAM_WEIGHT_MAX_WAIT_S` through `WeightedBudget.plan_max_wait_s`, #581) Record: [0074](../docs/decisions/0074-refuse-what-the-pacer-would-shed.md), `_eager_fetches`, `_fetch_forecasts`, `_rank_and_cut`, `_attach_late` and `_result`, with `_attach_aqi`, `_attach_cloud` and `_upstream_failure` beside them. Only `_find_candidates` and `_fetch_forecasts` are async generators, because each runs an upstream call on a task and relays its events while it waits; each ends with `Done` and its value, or with a terminal event. `_run_analysis` reads both inside `aclosing`, so a consumer that goes away cancels the phase's task before the close returns, not at collection; the last test in `test_analyze_phases.py` fails without it. Two rules keep the routes alike: `_eager_fetches` is the only reader of the eager conditions, and its one `Eager` value decides both the early fetch and the late skip; `_upstream_failure` is the only place a forecast fetch error becomes a `Failure`, the late refused key included (discovery's errors are mapped once in `discover()` and wrapped as they stand). `events.py` is what an analysis says: `Status`/`Progress`/`Failure`/`Refusal`/`Result` and `AnalyzeEvent`, plus `Done`, which carries a generator phase's value and never reaches a route, and `_drain` and `_STREAM_DONE`, the queue relay a phase uses to interleave progress with an upstream call on a task. `sse.py` is the stream's rendering: `_sse`, `_sse_error`, `_render_sse`, and `_with_keepalive` with `KEEPALIVE_INTERVAL_S`; `test_error_codes.py` reads it to check every `error` event carries its code, and fails if it finds none. The helpers the browser ports are `services/ranking.py`, and the candidate set it shares with `routes/destinations.py` is `services/candidates.py`
- `app/services/ranking.py` — every analysis helper the browser ports, and nothing that fetches: the forecast-bound tables `_LOWER_BOUNDS`/`_UPPER_BOUNDS` and `_filter_constraints`, the eager-fetch questions `_aqi_bounded` and `_cloud_eager`, `_sort_key`, `_assemble` with `_canonical_times`/`_aligned_aqi`/`_aligned_cloud`, the explicit top-N cut `_truncate_top_elevation`, and the refusal wording `_noun`/`_cap_detail`. Its own module so mirror rows 3, 17, 18, 28 and 29 name one place, and a reader can set it beside `clientAnalyze.ts` and `constraints.ts`. The names keep their underscores from the route they left, so a port comment still reads the same
- `app/services/candidates.py` — the candidate set both discovery routes build: `discover()`, the custom list (`_custom_dicts`, `_resolve_custom`, `_merge_custom` with `_coord_key`), the elevation band `_filter_elevation`, and the over-cap remedy (`_suggest_elevation_floor`, `_refusal_body`). Its own module because `POST /api/analyze` and `POST /api/destinations` must turn one request into one list, and a route importing another route's helpers hid that. `discover()` is discovery's four-branch mapping from failures to API errors, and is the only place `"OpenStreetMap is not available. Try again later."` is written. It calls `osm.query_osm` and `osm.enrich_custom` through the package, which is where every test patches them
- `app/routes/geocode.py` — `GET /api/geocode`, a thin Nominatim proxy paced by `NOMINATIM_GATE`; exists because the policy wants a real User-Agent a browser cannot set, and forbids autocomplete. A repeat search is answered from `GEOCODE_CACHE` before the gate, because the same policy asks callers to cache and an uncached search waits its turn in the queue (#571)
- `app/routes/config.py` — `GET /api/config`, the preview banner's `PREVIEW_BANNER`/`PREVIEW_PR`/`PREVIEW_COMMIT`
- `app/cache_headers.py` — the `Cache-Control` header by path class (#354), registered beside the security headers; the two read different headers so their order carries nothing
- `app/services/errors.py` — the upstream exception vocabulary (`UpstreamError`, `UpstreamRateLimited`, `ModelCoverageError`, `InvalidApiKeyError`), `classify_http_error`, and the 429 parser
- `app/services/wfigs_coverage.py` — the coarse, outward-biased outline of where WFIGS can see, published as a foreign member on `/api/wildfires` so an unchecked row reads `N/A` rather than clear
- `app/services/usfs_coverage.py` — the same for the closure feeds, one outline per kind (#551), because only Region 6 publishes trails: `trail` is the Oregon and Washington polygon (Region 6), and `area` adds Arizona and New Mexico (Region 3), Nevada and Utah, southern Idaho below the Salmon River, and western Wyoming (Region 4). `REGION_RINGS` holds each region's rings, and `area_coverage(regions)` composes the area outline from the regions a snapshot holds, so `collection_json` reads the area outline from the snapshot and a region whose feed failed reads "not covered". `COVERAGE_FOR`/`COVERAGE_JSON_FOR` are the outlines with every region present, and `covers(kind, lat, lon, regions)` is the tests' ray cast. `STATE_PROBES` is one point per state, each inside its own region's rings alone, for the browser: it asks the live area outline which of them it holds and names only those states in the Closure column's N/A hover, so a failed feed's states drop out of it (#567); the mirrored-constant manifest carries them across. Record: [0092](../docs/decisions/0092-closure-dash-is-no-order-found.md) Every outline is coarse and ~0.2° outward on land, and where two outlines meet one overlaps the other, since the browser asks whether ANY polygon holds a point. The bias gives way in two places: between Clarkston and Lewiston, where the border runs between two towns, along the Wind River and Absaroka divide in Wyoming, whose east side is the Shoshone, a Region 2 forest, and around two Region 5 units in Nevada (the Inyo's White Mountains and the Lake Tahoe Basin). It borrows `wfigs_coverage`'s ray cast rather than keeping a second one Record: [0068](../docs/decisions/0068-forest-orders-entry-closure-test.md)
- `app/services/bbox.py` — `parse_bbox`, the one reading of the `west,south,east,north` query parameter both bbox overlays take, with its `validation` 422s. Its own module so `/api/wildfires` and `/api/closures` cannot word the same malformed box two ways; the closure route tests compare the two bodies
- `app/routes/smoke.py` — `GET /api/smoke`: NOAA HMS smoke plumes for the whole of North America, with no bbox parameter, because a busy day measured under half a megabyte and a filter would be ceremony where NIFC's 16.5 MB genuinely needed one. `analysis_date` rides as a foreign member beside `fetched_at`: HMS publishes one dated file per day and the first analyst pass lands around late morning Eastern, so before then the fetch falls back to yesterday and that field is the only thing that says so Record: [0063](../docs/decisions/0063-smoke-no-bbox.md)
- `app/routes/wildfires.py` — `GET /api/wildfires`: the snapshot filtered to a bbox, at the fidelity the caller names, with `fetched_at` as a GeoJSON foreign member rather than a response header, so it survives being saved to a file (the SPA ignores it; it exists for API callers, who have no other way to know how current an answer is). Returns a raw `Response` so the stored feature text passes through unre-encoded; `response_model` still documents the shape. Its own rate bucket, the loosest of the six, tied with smoke and closures, because a pan costs no upstream call. The bbox is read by `services/bbox.py`
- `app/routes/closures.py` — `GET /api/closures`: the closure snapshot filtered to a bbox, by `kind` (`area` is the polygons of Regions 3, 4 and 6; `trail` is Region 6's lines and closed-site points together, because a closed trailhead is a closed way in) and at the fidelity the caller names. The wildfire route's shape throughout: a raw `Response` of stored feature text, `fetched_at` and `coverage` (the outline for the requested kind) as foreign members, the shared `parse_bbox` and `snapshot_or_503`, and its own rate bucket so a user with every overlay on does not spend one budget three times
- `app/routes/destinations.py` — `POST /api/destinations`: discovery without forecasts, **and** resolution of `custom_destinations` against OSM (the SPA's only per-analysis server call, now on the custom-only path too; shares the analyze rate-limit bucket). At least one of `polygon` or `custom_destinations` is required; a union comes back merged, custom rows winning by name or 5-decimal coordinate
- `app/routes/notfound.py` — `/api` catch-all returning a JSON 404 (or a 405 with `Allow`) instead of letting unknown API paths fall into the SPA static mount. Must stay the **last** router registered under `/api`. The bare `/api` has a route of its own on the same handler, because `/{path:path}` under the prefix never matches it. `not_found_body` is the one builder of the 404 body, so the gateway's copy (below) differs from it in the path alone. Record: [0081](../docs/decisions/0081-edge-404-is-the-apps.md)
- `scripts/generate_openapi.py` — writes/verifies the committed `backend/openapi.json`
- `scripts/generate_edge_not_found.py` — writes/verifies `backend/edge_not_found.json`, the status, body and headers the production gateway's own `404` must send (#565). The body is `not_found_body` with `this path`, and the headers are what the app actually sent on a `404` to a browser, so nothing in it is typed. `test_notfound.py` fails a stale file, and bluebird-helm's `Edge 404` workflow turns red when the chart's `-api-internal` route differs from the file on `main`. That workflow is deliberately not a required check, so nothing blocks on it: a header or CSP change here needs a paired chart PR that only review will ask for. Record: [0081](../docs/decisions/0081-edge-404-is-the-apps.md)
- `scripts/generate_weather_vectors.py` — regenerates `tests/data/weather_vectors.json` from the reference aggregation (see the vectors rule above)
- `scripts/generate_analyze_golden.py` — writes `tests/data/analyze_golden.json`, the golden record of what both analyze routes answer (#540): for each stubbed case, the JSON route's status, `Retry-After` and exact body, every `data:` line of the stream, and every argument each upstream fetch was given (the destinations, the window, the model, the endpoint split, the key and the discovery flags), which pins the eager and lazy AQI and cloud decisions and anything a restructuring carries from one phase to the next. A server error is recorded as the response a caller gets, and a case fails the render if it fetches or schedules a snow grid. `test_analyze_golden.py` fails on any byte of difference, so a restructuring of the analysis that is meant to move nothing proves it, and a change meant to move an answer regenerates the file and says why. The script and its test import nothing from the `routes/analyze/` package, so moving code within or out of it cannot edit the check that judges the move; the stubs replace the fetches on their service modules, which is also the only place any route test patches them. The same test fails any way code under `app/` reaches a stubbed fetch other than through the module a test patches, because a name bound that way escapes every stub: a direct, relative or star import from the owning module, or a discovery fetch reached through `osm.mirrors`/`osm.enrich` (ruff's banned-api cannot express it: it also flags the correct `weather.fetch_weather_batch`). No case reads the clock: windows start at the current hour and the stubs answer fixed stamps
- `scripts/write_third_party_licenses.py` — appends the Python half of the image's `third-party-licenses.txt` (#571): one block per distribution the interpreter can see, with every license file its `.dist-info` holds, found through the RECORD rather than the `License-File` header (httpx ships its text with no header naming it). The image build runs it after `pip install` from a bind mount, so it is not left in the image, and a distribution with no text fails the build. Standard library only, because it runs in the runtime stage where nothing else is installed. A script rather than app code because the pod never runs it; `tests/test_third_party_licenses.py` holds it over distributions written to a temporary directory. Record: [0086](../docs/decisions/0086-license-notices-built-into-the-image.md)
- `app/services/osm/` — everything this app asks Overpass, in three modules (#406); `__init__.py` re-exports them, and the routes call `osm.query_osm` and `osm.enrich_custom` through it. `query.py` is the query text and the reading of an element: `IMPLEMENTED_TYPES` gates which destination types are discoverable, `_CLAUSES` holds each type's QL as a *fragment* so several types union into one request, and `_ele_ft` is the one reading of an `ele` tag both other modules use. `mirrors.py` is the network: the 2-endpoint `OVERPASS_MIRRORS` table with its per-mirror budgets and timeouts, `query_osm`, and `_post_with_fallback`, the failover every Overpass request goes through. That failover fills each query's `[timeout:N]` from the attempt's own timeout (the builders leave `SERVER_TIMEOUT_TOKEN` in its place), and asks a mirror that failed inside `MIRROR_COOLDOWN_S` last rather than skipping it (#545); `reset_mirror_health` is what the conftest calls so one test's failure cannot reorder the next test's chain. `enrich.py` is `enrich_custom`, the other direction: one batched `around` query resolves caller-supplied coordinates to the nearest peak within `CUSTOM_MATCH_RADIUS_M` (150 m, measured — see the comment before changing it), filling elevation and `osm_id` only where the caller supplied none. Best-effort by construction: every failure path returns the rows unchanged, so an analysis never fails over an elevation, and each lookup stops waiting at `ENRICH_DEADLINE_S` because a pasted list waits on it before any forecast. It calls `mirrors._post_with_fallback` through the module, so a test patches `osm.mirrors` once and reaches both discovery and enrichment Record: [0061](../docs/decisions/0061-custom-match-radius-150m.md)
- `app/services/openmeteo_fetch.py` — the pipeline both Open-Meteo services run (#387): the cache-miss scan, the chunking at `BATCH_SIZE` and `MAX_CONCURRENT_BATCHES` (which live here, once), the weighted pacer and the in-flight slot, the timed request with its telemetry and classification, and the write-back. What the two services do **not** share is what a failed batch does, so `on_error` is a **required keyword argument with no default** — weather raises and fails the analysis, air quality degrades to null rows and the first 429 stops the batches behind it. A default either way fails silently, and `tests/test_openmeteo_fetch.py` fails if one is added or if a service re-declares a batch constant. The one automatic resume of a minutely 429 lives here too, behind the equally required `resume_minutely` (weather `True`, air quality `False`), because the wait must run outside the in-flight slot and the retry must pay its weight again, and only this loop holds either (#581); the wait is capped at a minute, the most a minutely quota can need. A degrading service's batch that came back unusable raises `BatchUnanswered` rather than returning null rows, because a null row is cached as "no data" for the TTL and an unusable answer is not that: its rows are null for this analysis and nothing of the batch is cached (#581). `request_openmeteo` takes the shared client rather than reaching for it, and `redacted_params`/`redacted_error`/`quota_label` live here because every request through it logs and labels the same way
- `app/services/aggregation.py` — the vector-pinned arithmetic and nothing else (#405): the weather and air-quality aggregates and series, the elevation adjustments, the freezing level's unit, the check that every other weather column, and the cloud request's 2 m temperature and dew point, carry the unit the request asked for (`_check_units`, #581), the stamp helpers, the variable list, and `_join_hours`, the join that makes a window split across two endpoints look like any other window. Its own module so a reviewer can read it beside its browser port, `frontend/src/utils/openMeteoAggregate.ts`: the two list the same functions in the same order, and `openMeteoAggregate.test.ts` fails when they drift. `PROVIDER` lives here because the one refusal this module raises names it and `weather.py` imports from here

It asks the pipeline for the one automatic resume of a minutely 429 (`resume_minutely=True`)

It reads `hour_param` from `weather.py`, which is where the window convention lives, and its aggregation from `aggregation.py`

- `app/services/http.py` — the one `httpx.AsyncClient` the Open-Meteo services share (forecast, archive, air quality, and their customer twins), closed by `main.py`'s lifespan, **and** the one `USER_AGENT`/`HEADERS` every fetching module sends (`osm/mirrors.py`, `nifc.py`, `usfs_closures.py`, `hms.py`, and `routes/geocode.py`, which had drifted to a second spelling of the same product; #388). The shared client itself sends no User-Agent, which is Open-Meteo's existing behaviour and not a thing to change quietly. httpx pools connections per *client*, so a client built inside the chunk loop discarded the pool and paid a fresh TCP+TLS handshake every batch: measured 2026-07-31 at ~540 ms per batch (720 ms per request cold, 178 ms warm). Batch size is **not** the lever here and was measured and left at 50 (issue #182): weight is per-location, so bigger batches buy no throughput under the pacer, and Open-Meteo's nginx caps the request URI at 8,192 bytes, which 250 locations of 7-decimal coordinates already fills to 7,485 Record: [0010](../docs/decisions/0010-shared-httpx-client.md)
- `app/services/cache.py` — TTL/LRU caches: discovery (~10 min per polygon+type), custom-coordinate resolution (~10 min per point *set*, order-independent), per-location forecasts (~15 min), and place searches (~10 min per query+limit). **Not** the wildfire snapshot: `TTLCache.get()` deletes an expired entry, and that entry is exactly what `nifc.py` must keep hold of
- `app/services/snapshot.py` — `SnapshotCache`, the singleflight, **stale-tolerant** holder the three snapshot overlays use (wildfires, smoke and closures; the snow grid too, through `current_or_schedule`): an aged snapshot is served immediately and refreshed *behind* the request, and the only states that mean "we cannot answer" are having never fetched at all and holding a snapshot older than `MAX_STALE_S` (24 hours), past which `get()` raises the error the last refresh failed with, so the route answers the cold cache's 503 rather than a fire map days out of date. Record: [0077](../docs/decisions/0077-snapshot-max-stale-24h.md) `current_or_schedule`, the snow grid's door, applies no such limit, because that answer states its own date on screen. Every refresh runs under one total deadline, `REFRESH_DEADLINE_S`, an `asyncio.timeout` like the elevation lookup's, because a caller on a cold cache is a request Cloudflare closes at 100 s and each upstream's `REQUEST_TIMEOUT_S` bounds one operation only; a failure, the deadline included, counts in `bluebird_forecast_snapshot_refresh_failures_total` (#580). Deliberately not a `TTLCache`: that one deletes an entry the moment it expires, which is exactly the value these must hold on to. It owns everything else the overlays share (#388): `cache_factory`, which wires the cache to one upstream's fetch and knobs and returns the module-level factory (`perimeter_cache`, `smoke_cache`, `closure_cache`) whose keywords a test overrides; `unavailable_message`; and `snapshot_or_503`, the one cold-cache answer every overlay route calls, so the status, the sentence and the `Retry-After` cannot differ between them. It raises `ApiError` from the services layer, as `ratelimit/client.py` already does, rather than leaving two copies of the raise in the routes
- `app/services/hms.py` — the NOAA HMS smoke snapshot behind `GET /api/smoke` (issue #121). One dated KML per day off NOAA's own file server, not an ArcGIS mirror of the same data — the shared-org-quota failure mode #203 removed from the fire overlay. The date is **Eastern**, because that is the shift the analysts work, and a UTC date would ask for tomorrow's file for five hours every evening; a 404 falls back one day, which is the normal morning state rather than an outage. Density lives in the placemark's `styleUrl` rather than in the data, in a vocabulary NOAA has changed once already (numeric to named, 2022-07-19), so an unrecognized style renders as Light with the raw value kept rather than being dropped. `ospo.noaa.gov/data/land/fire/smoke.kml` is advertised as current and is frozen at 2022-07-18: do not use it Record: [0017](../docs/decisions/0017-hms-smoke-feed.md)
- `app/services/nifc.py` — the national wildfire-perimeter snapshot behind `GET /api/wildfires` (issue #203). One paged ArcGIS query per fidelity (full-resolution for API callers, ~56 m simplified for the map picture and the proximity math — see the fireProximity bullet) covering the whole country with no geometry filter, which is both the smallest query to describe and the one that sidesteps the Aleutians straddling the antimeridian. Measured 2026-07-31 at 232 active fires: 16.5 MB full, 1.3 MB coarse, so the country fits in a pod and nothing keys on the caller's bbox. - `app/services/arcgis.py` — what both ArcGIS feeds (`nifc.py`, `usfs_closures.py`) answer alike, read once: `raise_for_arcgis_error` (the refusal inside an HTTP 200, worded by the caller), `page_flag`, `bounds` (the per-feature bbox walk, a Point answering zero width) and `fetch_pages`, the offset pager that runs each page's parse off the event loop. `page_flag` exists because `f=geojson` puts `exceededTransferLimit` under the collection's `properties`, not at the top level where `f=json` puts it (measured 2026-09-30 on both services): the old top-level reader in `nifc.py` would have served page one alone and never showed it, because fires never passed one page, while closure lines arrive in two. - `app/services/usfs_closures.py` — the Forest Service closure-order snapshot behind `GET /api/closures` (#550, #551), modelled on `nifc.py`: Region 6's three layers of one ArcGIS service (closed sites as points, closed trails and roads as lines, area closures as polygons), five queries per refresh (the points once, the lines and polygons at both fidelities), plus the forest-order feeds of Regions 3 and 4 (`OrderFeed`, `ORDER_FEEDS`), three queries each, all on one client and held as feature text plus a bbox. Regions 3 and 4 publish every standing order with no status, so `fetch_forest_orders` reads them in two phases: every live order's attributes (`ORDER_WHERE`: not rescinded, started, end date not past, all against now), filtered by `is_area_closure`, then the geometry of the passing `objectIds` alone at both fidelities, and nothing when none pass, because Region 4's live geometry is 29.9 MB and five orders pass. `is_area_closure` is TJ's rule (2026-09-30): the `cfr` text cites 261.52(e) or 261.53(e) (each section read up to the next section number, so list forms count), or the description or name says entry is prohibited in a sentence that names no permit; `ordertype` is not the test, since Region 4 files reckless driving as a "Safety Closure". Three vetoes narrow it (TJ, 2026-10-01, #568), and each beats both signals: `ORDER_KIND_VETO` reads the type and name for a motor vehicle order or a Stage 1 or 2 fire restriction, `TEXT_SCOPE_VETO` reads an entry sentence limited to a motorized vehicle or to posted ground (an unlimited entry sentence in the same order still passes it), and `EXCLUDED_ORDERS` names by `ordernum` the orders no text rule can catch, one comment each, because object IDs change when a layer is reloaded. It also refuses an order whose start date is ahead, which `ORDER_WHERE` already leaves out, so the whole rule is one testable function. A sentence ends at a period before a space, never inside `12.5`, `C.F.R.` or after `Rd.`, so a permit clause stays with its entry words. One type passes by itself: `STAGE_THREE_FIRE_CLOSURE` (the whole `ordertype` "Fire Closure - Stage 3") counts with no citation and no entry words, because Region 4 files its fire area closures that way, unless an entry sentence in it names a permit, a vehicle or posted ground (TJ, 2026-10-01). A failed Region 3 or 4 feed drops that region with a warning rather than failing the snapshot, and `Snapshot.regions` records what it holds; a failed Region 6 query still fails the fetch. `_to_order_closure` maps each order onto Region 6's property names so one feature shape reaches the browser, and every feature carries `ClosureSource` (`R03`/`R04`/`R06`) and `ClosureType` (null on Region 6) for API callers. `areas_full` joins Region 6, then 3, then 4. The snapshot holds two kinds rather than three layers: `area` is the polygons and `trail` is the lines followed by the points, which sit in both fidelities because a point has no shape to simplify. The coarse tolerance is `nifc.COARSE_OFFSET_DEG`, imported rather than spelled again (mirror row 10). `outFields` is one list per layer because ArcGIS answers a field a layer lacks with a 400. Region 6's `ClosureStatus='Active'` is trusted as sent and nothing filters it on the end date, though some active orders carry a past one (TJ, 2026-09-30). The TTL is 30 minutes because the orders are edited by hand a few times a week Record: [0067](../docs/decisions/0067-region-6-closure-orders.md), [0068](../docs/decisions/0068-forest-orders-entry-closure-test.md), [0079](../docs/decisions/0079-forest-order-vetoes-and-start-date.md)
- `app/services/snodas.py` — today's snow depth for any coordinate, from one national grid the pod holds (#449). NSIDC publishes each day's SNODAS products as one tar; this pulls the **unmasked** snow depth member out of it by its `1036` product code (24.1N to 58.23N, 130.5W to 62.25W: the contiguous United States, southern Canada and northern Mexico, which is the same box the map's snow layer draws), reads the geometry out of the `.txt.gz` header beside it rather than assuming one (NSIDC has moved the masked extent once), and keeps the 8192x4096 array of big-endian int16 millimetres as `bytes` — 64 MiB, never written to disk, because the pod runs `readOnlyRootFilesystem`. A `SnapshotCache` through `cache_factory` like the two overlays, with two differences that are the whole of its design. The fetch checks the HELD snapshot's date first and answers with it unchanged for most of the day, so an hourly refresh is one `HEAD`; the day's tar is published around 13:15 UTC and a 404 falls back one day, the `hms.py` pattern.
